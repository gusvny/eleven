# 项目生命周期操作手册（add/list——票①初版）

> 立项真源 = `notes/epics/project-lifecycle.md`（票①=t260904-10：`sandbar project add|list`
> 注册表接入面；remove 属票②，本版只挂恒红点位）。契约真源 =
> `docs/design/sandbar项目接入契约v1.md` ①a/①b/②a。装载真源 =
> `server/dsh/temporal-poc/shared.py`（Python）与 `server/dsh/suyou-projects.ts`（TS，
> workbench API 消费方）——两侧同一注册表、语义同构。

## 命令面

```bash
# 注册新项目（fail-closed 校验 + 原子写 + 接入体检报告）
sandbar project add --key <key> --name <显示名> --dir <项目根绝对路径> [--json]

# 全列注册与隔离条目 + 票计数（Temporal 不可达时降级提示，命令不红）
sandbar project list [--json]

# 摘除项目（票②交付：在飞闸/退役移位/摘除报告/purge 闸；本版恒红，不提供半成品摘除）
sandbar project remove --key <key> [--json]
```

出口码：`0`=绿；`1`=红（语义拒收，FailClosed 通道）；`2`=用法错（argparse 面）。
`--json` 三命令机器可判，UI（票③）与脚本走同一口径。

## 注册表在哪

- per-key 目录模式（现行）：`~/.sandbar/projects/<key>/project.yaml`，可用环境变量
  `SANDBAR_PROJECTS_DIR` 指到其他根（测试/多机场景）。
- legacy 单文件模式（只读兼容）：环境变量 `SUYOU_PROJECTS_YAML` 在位时运行时读旧
  单文件。**此模式下 `project add` 拒收**——写 per-key 目录运行时读不到（静默无效），
  工具宁可拒绝也不制造脑裂。移除该 env 后重试即可。
- 首次对不存在的注册表根执行 add/list 时，装载器会从迁移种子
  `server/dsh/projects.yaml` 自动播种存量条目并落 `.migrated` 标记——这是装载器
  现行语义，工具不绕过不预判。

## add：前置校验清单（任一不过=拒收，注册表零残留）

| # | 闸 | 拒收条件 | 文案可辨点 |
|---|---|---|---|
| a | key 白名单 | 不过 `^[a-z0-9][a-z0-9-]{0,40}$`（小写字母/数字/中划线，小写字母或数字开头，41 字符上界） | 「key 不合法」 |
| b | 单根模型 | `--dir` 给了 0 个或多个（多目录=归属歧义；多 repo 项目请用父目录作根） | 「单根目录模型」 |
| c | key 未注册 | 已注册（含隔离条目同名）→ **幂等重跑同判**（同 exit、同文案），绝不改写 | 「已注册」「幂等」 |
| d | 根不交叉 | 与既有项目根相等/互为父子嵌套/路径交叉 → 报**两个 key** | 「交叉或互为父子」 |
| e | 非 legacy | `SUYOU_PROJECTS_YAML` 在位 | 点名 env 并指路 |
| f | 装载先行 | 前置装载走装载器全语义（自动播种/现场判定/混合现场 fail-closed），装载不过=红 | 「注册表装载失败」 |
| g | 标量值 | name 非空、首尾空白会被 trim；name 与根目录不含 `#`、不含换行（写入即被装载器注释剥除/破结构） | 点名 `name`/`root_dir` |

写入是原子的：先对 `<root>/<key>/project.yaml` 做 `O_CREAT|O_EXCL` 独占认领（并发同
key 双 add 恰一成一拒，输家报幂等拒收，无静默覆盖），再 tmp+rename 落内容，最后写后
自检（装载器可解析+全表零隔离）。任一步失败即回滚清理，注册表不留半成品。

**目录可以先在**：`<注册表根>/<key>/` 目录与 `credentials.yaml` 允许在 add 之前手工
布置（契约①b 用户旅程）；排他锚是 project.yaml 文件而不是目录。

## add：接入体检报告（黄牌只提示、不代写、不阻塞，exit 0）

| 类 | 在位/声明时 | 缺失/未声明时 |
|---|---|---|
| verify.yaml | —（承载位置由项目注册自定，契约②a，`.sandbar/` 非硬性路径；工具不猜路径） | 黄牌「未声明 verify.yaml 位置」：第一张 dev-lane 票若需要集成测试而项目未自备，会在 integration 道红 |
| credentials | 绿行「per-key credentials.yaml 在位」 | 黄牌「回落 dsh 平台文件」（`DSH_HOME/.credentials.yaml` → `~/.dsh/.credentials.yaml`，①b 弃用窗口口径）。**add 不代拷**（260904 定案） |
| paths | —（本工具不产 paths 节） | 黄牌「未声明 paths 节」：roles_dir/model_routes 按现行约定回落 |

工具不代写项目仓任何文件——项目策略项目自备（契约：机制在 IDE，策略在项目）。

## list：报告口径

- 注册条目全列（key/显示名/根目录/票计数：在飞、完结、已归档）。
- 隔离条目全列，原因含 `<dir>/project.yaml` 定位字面（坏文件可顺手找到）。
- 无 project.yaml 的保留目录（如 `data/`）不列（装载语义=跳过）。
- 票计数走子进程查 Temporal（`client.py ticket-list` 按 ProjectKey）。**两种降级态
  可辨且都不红**（exit 0）：服务不可达（连接失败/超时/输出异常）与 temporalio SDK
  缺失——依赖缺失不会被吞成「无数据」（KI-039 教训），也不与不可达混同。
  要查真票先 `sandbar up` 起 server 后重试。
- `--json`：`{projects:[{key,name,dirs,tickets,tickets_state,tickets_note}],
  quarantined:[{key,dir,error}], mode}`，与人读同列同构。

## 故障口径

- **并发同 key 双 add**：恰一成一拒；赢家条目 name/dirs 自洽；输家重装载后报幂等
  拒收。不同 key 并发天然不冲突（各写各目录）。add 定位为单宿主操作面命令，无需
  分布式锁。
- **写失败**（磁盘满/权限等）：报「已回滚（注册表零残留）」，已创建的空目录会一并
  清掉；预布置了 credentials 的目录原样保留。
- **混合现场**（注册表根有内容但无 `.migrated` 标记且与种子部分相关不可复现）：
  装载器 fail-closed，按报错人工处置（补标记/清目录重迁/移除迁移源三选一），工具
  不猜。
- **`project remove` 恒红**（票②未交付）：摘除请勿手删 `<key>/` 目录——归档
  （`data/tickets/`，审计真源）会随目录蒸发。等票②的退役移位 + purge 显式旗，或
  按立项单红线走人工口径（先确认无在飞票）。

## 红线

- console（3099）永属用户操作面，本命令族与它零接触。
- 注册表**读**开放（list/lookup），**写**（add/remove/purge）只落本安装器 CLI
  （宿主操作面），不进工具桥——dirs 是工单锚定闸的规则本体，被闸裁判者不得自改边界。
- 审计真源不蒸发：在 remove/purge 语义落地前，任何人不得手删含 `data/` 的 key 目录。
