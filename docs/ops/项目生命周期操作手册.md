# 项目生命周期操作手册（add/list/remove）

> 立项真源 = `notes/epics/project-lifecycle.md`（票①=t260904-10：`sandbar project
> add|list`；票②=t260904-14：`sandbar project remove` 可逆摘除）。契约真源 =
> `docs/design/sandbar项目接入契约v1.md` ①a/①b/②a。装载真源 =
> `server/engine/shared.py`（Python）与 `server/suyou-projects.ts`（TS，
> workbench API 消费方）——两侧同一注册表、语义同构。

## 命令面

```bash
# 注册新项目（fail-closed 校验 + 原子写 + 接入体检报告）
sandbar project add --key <key> --name <显示名> --dir <项目根绝对路径> [--json]

# 全列注册与隔离条目 + 票计数（Temporal 不可达时降级提示，命令不红）
sandbar project list [--json]

# 摘除项目（可逆：project.yaml 退役改名，默认不删任何数据）
sandbar project remove --key <key> [--json]
sandbar project remove --key <key> --dry-run     # 全闸预演：只出将改名/将删清单，零现场变更
sandbar project remove --key <key> --purge-data          # 摘除后删 <key>/data/（过闸才删）
sandbar project remove --key <key> --purge-credentials   # 摘除后删 credentials.yaml（独立旗）
sandbar project remove --key <key> --confirm-last        # 摘最后一个注册项目时必带
```

出口码：`0`=绿；`1`=红（语义拒收，FailClosed 通道）；`2`=用法错（argparse 面）。
`--json` 三命令机器可判，UI（票③）与脚本走同一口径。

## 注册表在哪

- per-key 目录模式（现行）：`~/.sandbar/projects/<key>/project.yaml`，可用环境变量
  `SANDBAR_PROJECTS_DIR` 指到其他根（测试/多机场景）。
- legacy 单文件模式（只读兼容）：环境变量 `SUYOU_PROJECTS_YAML` 在位时运行时读旧
  单文件。**此模式下 `project add` / `project remove` 拒收**——写 per-key 目录运行时
  读不到（静默无效；对 remove 而言=「假成功摘除」），工具宁可拒绝也不制造脑裂。
  移除该 env 后重试即可。
- 首次对不存在的注册表根执行 add/list 时，装载器会从迁移种子
  `server/projects.yaml` 自动播种存量条目并落 `.migrated` 标记——这是装载器
  现行语义，工具不绕过不预判。

## add：前置校验清单（任一不过=拒收，注册表零残留）

| # | 闸 | 拒收条件 | 文案可辨点 |
|---|---|---|---|
| a | key 白名单 | 不过 `^[a-z0-9][a-z0-9-]{0,40}$`（小写字母/数字/中划线，小写字母或数字开头，41 字符上界） | 「key 不合法」 |
| b | 单根模型 | `--dir` 给了 0 个或多个（多目录=归属歧义；多 repo 项目请用父目录作根） | 「单根目录模型」 |
| c | key 未注册 | 已注册（含隔离条目同名）→ **幂等重跑同判**（同 exit、同文案），绝不改写 | 「已注册」「幂等」 |
| d | 根不交叉 | 与既有项目根相等/互为父子嵌套/路径交叉 → 报**两个 key** | 「交叉或互为父子」 |
| e | 非 legacy | `SUYOU_PROJECTS_YAML` 在位 | 点名 env 并指路 |
| f | 装载先行 | 前置装载走装载器全语义（自动播种/现场判定/混合现场 fail-closed），装载不过=红 | 「注册表装载失败」 |
| g | 标量值 | name 非空、首尾空白会被 trim；name 与根目录不含 `#`、不含换行（写入即被装载器注释剥除/破结构） | 点名 `name`/`root_dir` |

写入是原子的：先对 `<root>/<key>/project.yaml` 做 `O_CREAT|O_EXCL` 独占认领（并发同
key 双 add 恰一成一拒，输家报幂等拒收，无静默覆盖），再 tmp+rename 落内容，最后写后
自检（装载器可解析+全表零隔离）。任一步失败即回滚清理，注册表不留半成品。

**目录可以先在**：`<注册表根>/<key>/` 目录与 `credentials.yaml` 允许在 add 之前手工
布置（契约①b 用户旅程）；排他锚是 project.yaml 文件而不是目录。

## add：接入体检报告（黄牌只提示、不代写、不阻塞，exit 0）

| 类 | 在位/声明时 | 缺失/未声明时 |
|---|---|---|
| verify.yaml | —（承载位置由项目注册自定，契约②a，`.sandbar/` 非硬性路径；工具不猜路径） | 黄牌「未声明 verify.yaml 位置」：第一张 dev-lane 票若需要集成测试而项目未自备，会在 integration 道红 |
| credentials | 绿行「per-key credentials.yaml 在位」 | 黄牌「回落 dsh 平台文件」（`DSH_HOME/.credentials.yaml` → `~/.dsh/.credentials.yaml`，①b 弃用窗口口径）。**add 不代拷**（260904 定案） |
| paths | —（本工具不产 paths 节） | 黄牌「未声明 paths 节」：roles_dir/model_routes 按现行约定回落 |

工具不代写项目仓任何文件——项目策略项目自备（契约：机制在 IDE，策略在项目）。

## remove：摘除四步闸序（契约①a-1；任一不过=exit 1，零现场变更）

| # | 闸 | 拒收条件 | 文案可辨点 |
|---|---|---|---|
| 0 | 模式闸 | `SUYOU_PROJECTS_YAML` 在位（退役/purge 写 per-key 目录=运行时读不到的假成功摘除） | 点名存量 env |
| 1 | 装载/key 闸 | 注册表装载失败；key 未注册（与隔离条目同名区分报，含 `<dir>/project.yaml` 定位）；key 不合法 | 「未注册」「隔离」 |
| 2 | 最后条目闸 | 摘最后一个注册项目且未带 `--confirm-last`（零条目警告=装载器空表抛错语义点名） | 「--confirm-last」「空表」 |
| 3 | 在飞闸 | Temporal 按 ProjectKey 查 RUNNING 票非空 → **拒摘并逐条报票号**；Temporal 不可达/SDK 缺失/通道坏 JSON → **fail-closed 拒摘，无绕过旗**（260904 拍板：要摘先 `sandbar up`；引擎真死透走手工路径并先读红线节） | 票号清单；「unreachable」「sdk-missing」两态可辨（KI-039） |

四闸全过 → **退役移位**：`<root>/<key>/project.yaml` 原子改名为同目录
`project.yaml.retired-<UTC>`（不删任何数据；装载器对无 project.yaml 的子目录本就跳过
=条目即刻隐身；**可逆**：改回文件名即恢复条目）。同目录已有退役文件（同秒碰撞）=拒收
点名人工处置。移位后写后自检（装载不再列本 key、全表零变化），自检失败即回滚改名；
回滚前发现 project.yaml 又在位（并发 add 重建）→ 放弃回滚报「现场已变，请重跑」，
绝不覆盖他人新条目。

**摘除报告**：data/（归档+metrics）与 credentials.yaml 字节数账目、closed 未归档差集
黄牌（列票号）、项目根 `.lane/` 各票泳道清单（**只报不删**，指路 teardown/手工清理）、
摘最后一个项目时的零条目警告。`--json` 与人读共用口径。

**数据处置三态显式分离**（审计真源不蒸发）：

- 默认：`data/` 与 `credentials.yaml` **字节不动**。
- `--purge-data`：前置「closed 全归档」闸——未归档差集 = Temporal COMPLETED 票号集合
  − fs 已归档集合（**判定锚 = `<id>/archive.json` 三态**：在位且含 `schema: v1`=已归档；
  目录在/manifest 缺=未归档，进差集；manifest 畸形=直接 fail-closed 点名
  `<id>/archive.json`，不静默归侧不静默重产）。差集非空=拒并列票号；过闸才删 `data/`。
- `--purge-credentials`：独立旗，只删 `credentials.yaml`；可与 `--purge-data` 组合。
- `--dry-run`：全闸照跑、退役/删除不执行，输出将改名/将删清单（路径+字节+票计数），
  注册表根字节级零变更。

**再接入（re-add）**：摘除后同 key 重跑 `project add` 即恢复注册；`data/tickets/`
归档链连续不断（默认摘除根本没碰数据）。

## list：报告口径

- 注册条目全列（key/显示名/根目录/票计数：在飞、完结、已归档）。
- 隔离条目全列，原因含 `<dir>/project.yaml` 定位字面（坏文件可顺手找到）。
- 无 project.yaml 的保留目录（如 `data/`）不列（装载语义=跳过）。
- 票计数走子进程查 Temporal（`client.py ticket-list` 按 ProjectKey）。**两种降级态
  可辨且都不红**（exit 0）：服务不可达（连接失败/超时/输出异常）与 temporalio SDK
  缺失——依赖缺失不会被吞成「无数据」（KI-039 教训），也不与不可达混同。
  要查真票先 `sandbar up` 起 server 后重试。
- `--json`：`{projects:[{key,name,dirs,tickets,tickets_state,tickets_note}],
  quarantined:[{key,dir,error}], mode}`，与人读同列同构。

## 故障口径

- **并发同 key 双 add**：恰一成一拒；赢家条目 name/dirs 自洽；输家重装载后报幂等
  拒收。不同 key 并发天然不冲突（各写各目录）。add 定位为单宿主操作面命令，无需
  分布式锁。
- **写失败**（磁盘满/权限等）：报「已回滚（注册表零残留）」，已创建的空目录会一并
  清掉；预布置了 credentials 的目录原样保留。
- **混合现场**（注册表根有内容但无 `.migrated` 标记且与种子部分相关不可复现）：
  装载器 fail-closed，按报错人工处置（补标记/清目录重迁/移除迁移源三选一），工具
  不猜。
- **手删 `<key>/` 目录仍然禁止**：remove 落地后这是**旁路**——归档（`data/tickets/`，
  审计真源）会随目录蒸发，且绕过在飞闸/purge 闸。摘除一律走 `sandbar project remove`；
  Temporal 真死透的应急手工摘除先确认无在飞票并自担闸责（红线节）。
- **remove 回滚现场已变**：写后自检失败且 project.yaml 又在位（并发 add 重建）→
  放弃回滚、报「现场已变，请重跑」——不会覆盖新条目；此时退役文件仍在，人工核对后
  重跑 remove 或改回文件名恢复。

## 红线

- console（3099）永属用户操作面，本命令族与它零接触。
- 注册表**读**开放（list/lookup），**写**（add/remove/purge）只落本安装器 CLI
  （宿主操作面），不进工具桥——dirs 是工单锚定闸的规则本体，被闸裁判者不得自改边界。
- 审计真源不蒸发：手删含 `data/` 的 key 目录是永久禁区（remove 的 purge 语义之外
  任何路径不得删归档）；`--purge-data` 只在 closed 全归档差集为空时才会动手。
