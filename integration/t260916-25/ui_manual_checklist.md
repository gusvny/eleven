# dsh 升级 stage 台人工测试清单（t260916-25）

> ⚠ **只读警示**：本 stage 控制台连接【生产 Temporal 与项目注册表】。UI 上的写
> 操作（建票 / 改配置 / 发起会话调工具）会直接打到生产！本清单所有条目均为
> 只读浏览或最小成本操作，请勿执行任何破坏性写操作。

## 怎么用

```sh
# 起台（一条命令；换版本/端口/位置用对应参数）
server/tools/stage_console.sh start --version 0.1.5-rc.2
# 输出里拿带 token 的 URL，浏览器打开后按下面 M0-M9 逐条走查；
# 每条记录 ✅/❌+备注到「实测记录」列。走查完：
server/tools/stage_console.sh stop
```

- 自动断言（`selfcheck`）绿只代表「实测过的事实下限」没破；本清单管**观感级**
  的 UI break（排版/交互/主题/流式），两者互补，缺一不可。
- 升级走查 = 同一台机器先对 0.1.1（`--dsh-root /opt/homebrew/lib/node_modules/@deepseek-ai/dsh`）
  走一遍、再对目标版本走一遍，逐条对比。
- 接缝级出处见同目录 `ui_seam_matrix.md`（每条清单项标注对应矩阵行）。

## 走查项

### M0 冒烟（矩阵行 3）
- [ ] 打开带 token URL，首页正常渲染（无 401/白屏）
- [ ] 打开浏览器 DevTools console：**无任何报错**（M9 会再总检一次）

### M1 旧会话列表与打开（矩阵行 8）
- [ ] 侧栏能看到拷入的旧会话（prepare 默认拷最近 10 个，目录名是扁平化路径如 `--Users-xingu-Documents-sandbar--`）
- [ ] 任选 2~3 个旧代（v0）会话点开：**能打开**，会话列表/消息骨架不崩

### M2 会话日志视图正文完整性（矩阵行 8，**本票重点**）
> 背景实测：0.1.5 不再写 assistant/chunk、reasoning-chunks 事件。
- [ ] 旧会话日志视图：**助手正文是否完整**（无截断/空段/乱序）
- [ ] 旧会话：**推理流（thinking）视图**是否还有内容或合理降级（空区不吓人）
- [ ] 新版写的会话在同一视图里显示是否正常（对照）

### M3 用量页 token 数值（矩阵行 9，票面疑点）
- [ ] 用量页能打开，in/out 数值有数（非全 0/NaN）
- [ ] **cacheRead 是否恒 0**（票面手工疑点——若恒 0 记录下来，属用量面 break 候选）

### M4 实时流式视图（成本敏感，见警示）
> ⚠ 发新会话会真实调用模型（花钱）；请在输入里**不触发任何工具**的纯闲聊
> （如「用一句话介绍你自己」），并把工具选择调到最小。
- [ ] 新会话首字出现时间正常（无长时间空白后一次性吐完）
- [ ] 流式渲染过程无闪断/重复块/乱序

### M5 管理台插件三页（矩阵行 5/7）
- [ ] 管理台「工具直调」页：列表有数、页不崩
- [ ] 管理台「审计流水」页：流水有数、时间线正常
- [ ] 管理台「模型路由」页：路由表与 server/model-routes.yaml 一致
- [ ] （sandbar-temporal-tools 无浏览器半属预期——它出现在 UI 才要警惕）

### M6 knowledge / providers 页（矩阵行 7）
- [ ] knowledge 页打开不崩、知识库列表可见
- [ ] providers 页打开不崩、provider 列表与 ~/.dsh/.credentials.yaml 的账号对得上

### M7 明暗主题（观感级）
- [ ] 切换明/暗主题：全局生效，无残留亮/暗补丁块
- [ ] 刷新后主题记忆保持

### M8 workbench（工单数据来自**生产** Temporal——只读浏览！）
