# notes/ — 讨论与立项的工作区

> **本目录不是知识库。** 这里放半成品：讨论纪要、立项单、决策速记、债务台账。
> agent 干活时**不得**把本目录作为上下文加载（知识库只有 `docs/`）。
> （自 suyou 迁入适配，260904；机制真源沿革见 suyou 仓同名文件。）

## 目录结构

| 目录/位置 | 放什么 | 生命周期 |
| --- | --- | --- |
| `inbox/` | 灵感与素材速记（未评估） | 速记 → 评估 → 转讨论/立项，或注明原因丢弃 |
| `discussions/` | 讨论纪要（调研、方案探讨） | 探讨中 → 有结论 → 转立项或搁置 |
| `epics/` | 立项单（一个交付攻坚一个文件） | 已立项 → 执行中 → 已归档 |
| `debts/` | 债务台账（known-issues 等） | open → closed（附票号） |
| 根级单文件 | 决策速记（如 `会话tab全项目显示决策.md`） | 宿主拍板即定档；被 epic 吸收后注链接 |

## 与 docs/ 的分工（毕业规则）

- `docs/` 只接收**定稿**：系统设计、协议、规格——系统真源，持续维护（本仓 docs/ = 引擎/插件/基建域知识库，260904 迁入）。
- `notes/` 放**过程**：为什么做、怎么拆的、做到哪了——有始有终。
- 判断法则：半年后一个新 agent 要改代码，他需要读这份文档吗？
  需要 → `docs/`；不需要（过程记录、决策缘由） → `notes/`。
- **反向桥**：文档从 `notes/` 毕业进 `docs/`（或被立项重大修改）时，在对应章节末尾
  加一行来源标签：`> 来源立项：<代号>（决策缘由见 notes/epics/<代号>.md）`。
  这是从「是什么」跳回「为什么」的桥；标签给人看，agent 不需要顺着它读 `notes/`。

## 讨论纪要约定（discussions/）

文件名：`YYMMDD-<主题>.md`。每份纪要开头必须有状态行：

```
状态：探讨中 | 已有计划 | 已转立项 | 已搁置
```

- 没结论也要记「当时为什么停」——这是最容易丢、最值钱的信息。
- 转立项后在状态行注明立项单代号。

## 立项单约定（epics/）

文件名即代号：`<代号>.md`。代号规则：英文小写短词（可带连字符），全项目唯一，
开工单时作为 Temporal Search Attribute `EpicCode` 的值（强校验，档必须在位）。

立项单只记四样东西（其余由工单和 Temporal 承载）：

1. **目标与验收标准**——这个立项整体做到什么程度算完
2. **交付文档**——本立项要在 `docs/` 落地/更新的文档清单（验收时逐条核对，防止"工单全绿但文档欠债"；integration 在 merge 关卡执行核对）
3. **关键决策**——为什么这么拆、中途为什么改方向
4. **状态与归档快照**——收尾时跑一次 `EpicCode` 查询，把工单清单和结论固化进来再归档

**不手工登记工单清单**：工单归属查 Temporal（`EpicCode = "<代号>"`），
工单做了什么看工单自己的交付记录。

## 状态回顾

定期（建议每周）扫一遍本目录：探讨中的要么推进要么明确搁置；
已有计划的要么立项要么降级；执行中的立项单核对验收进度；open 债务核对有没有票认领。
