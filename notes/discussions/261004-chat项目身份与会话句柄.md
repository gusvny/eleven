## 1. 现状（读代码，非推测）

- **项目色**：`server/plugins/workbench/src/shared/project-color.ts` 的 `projectColor(key)`——
  确定性哈希（FNV-1a 32bit → 10 色调色板），同 key 恒同色；撞色概率约 1/10（模块头注自己声明了），
  升级路径写好了但没接：`projects.yaml` 加可选 `color` 字段覆盖哈希值。
- **右栏 chat 的装饰**：`chat-project-band.ts` 只给平台滚动体加「顶部 3px 项目色边 + 右上角零高角标（10px 等宽显示项目 key）」，
  另有 `chat-project-tag.ts` 给**每条用户消息**加项目 chip。**确实弱**：3px 细边 + 小角标，
  余光扫不到，切换项目时容易看错在哪个 chat 下。
- **会话账册**：`src/shared/sessions.ts` 的 `OpenedEntry{ id, project, cwd, lastOpenedAt, title?, seq? }`，
  存 **localStorage**（`sandbar-workbench-opened-sessions-v1`，`session-ledger-store.ts`）。
  `id` 是 dsh 的会话 uuid；`seq` 是**项目内登记序号**（显示在会话 tab 上，关闭不回收）。
  ⇒ 宿主说的「映射存 localStorage、换 origin 就丢」就是这个账册；「id 用数字」= `seq` 被当作 id 在用。

## 2. 设计

### 2.1 右栏 chat 的「项目身份带」（要一眼认出）

一条**常驻身份带**，sticky 在 chat 栏顶部（mock 已画）：

| 元素 | 规格 |
| --- | --- |
| 带面 | 高约 32px；底色 = 项目色 **14%** 混白/混底（`color-mix(in srgb, <color> 14%, var(--panel))`） |
| 带底 | **3px 实色**下边线（项目色全色）——比现在的 3px 顶边更靠近视线中心 |
| 内容 | 9px 方形色块 + 项目 key（12px/600）+ **会话句柄**（见 §2.3，11px 等宽灰）+ 右侧 `Sessions N` 切换钮 |
| 整栏 | **5% 项目色洗**（`color-mix(... 5%, var(--panel))`）——余光可辨 |
| 输入面 | 输入框 focus 边框与发送按钮 hover 取项目色（当前动作也带项目身份） |
| 消息级 | 保留 `chat-project-tag` 的每条消息 chip（不动） |

**验收口径**：切换项目时，右栏的**色相**必须变（不是只变文字）；截图对比两项目的带面/带底/洗色三者都要不同；
色盲场景下靠「项目 key 文字 + 句柄」兜底（颜色不是唯一通道）。

### 2.2 会话账册落项目（不再只存 localStorage）

- **真源**：`<projects_root>/<key>/sessions.json`
  ```json
  { "version": 1,
    "sessions": [ { "session_id": "session-09ca0247-…", "handle": "executor", "title": "",
                    "opened_at": 1791080000000, "last_opened_at": 1791092000000,
                    "cwd": "/Users/user/Documents/sandbar" } ] }
  ```
- **localStorage 降级为缓存**：可丢，丢了从项目文件重建（读失败/坏 JSON → 空表，不崩，沿用既有容错纪律）。
- **写路径**：UI → 宿主 API（workbench 宿主侧写项目目录，与 `watchdog.json` / `executor-grants.json` 同族，**宿主专属**；
  执行器可读不可写）。
- **迁移**：首次打开读旧 localStorage 账册，能读到的条目写入项目文件（**同一个 origin 内可迁**）；
  宿主这次丢的那份（旧 `localhost` origin）已经拿不回来——认账，不做考古，只在文件里从这一刻起记全。
- **好处**：换 origin / 换端口 / 重启 console 都不丢；可 `grep`；项目级事实与项目其它账（授权、动作、看板）同处一地。

### 2.3 会话句柄（id 不用数字）

**句柄 = 可读短名 · 短码**，例：`executor`、`panel-copy · 9ca0`、`metrics-docs · 4b71`。

| 部分 | 规则 |
| --- | --- |
| **短码** | 会话 uuid 的前 4 位十六进制（`session-09ca0247-…` → `09ca`）；项目内撞码则扩到 6 位。**稳定、可引用** |
| **短名** | 建会话时从**第一句话**取 2–3 个词的 slug（`panel-copy`、`doc-face`、`inspection`）；用户可重命名覆盖（`title`），显示用重命名、**句柄不变** |
| **执行器会话** | 固定名 **`executor`**（本项目固定角色，不带码、不参与登记序号） |
| **`seq`** | 保留在文件里做**历史排序**，但**不再当引用显示**（宿主：数字当 id 怪） |
| **一致性** | 同一套句柄出现在四处：**左栏会话行 / 右栏 chat 身份带 / 请求账引用（§7.8 的 `#a3f2` 同族）/ 票详情** |

**为什么不用纯数字**：数字不带语义（看不出这是哪个会话）、跨项目会重复（每个项目都有 1 号）、
当引用时歧义（「第 3 个会话」得先问哪个项目）。短名给语义，短码给唯一与稳定。
