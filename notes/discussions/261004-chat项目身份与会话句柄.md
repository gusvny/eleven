## 2. 设计

### 2.1 右栏 chat 的「项目身份带」（要一眼认出）

一条**常驻身份带**，sticky 在 chat 栏顶部（mock 已画）：

| 元素 | 规格 |
| --- | --- |
| 带面 | 高约 32px；底色 = 项目色 **14%** 混白/混底（`color-mix(in srgb, <color> 14%, var(--panel))`） |
| 带底 | **3px 实色**下边线（项目色全色）——比现在的 3px 顶边更靠近视线中心 |
| 内容 | 9px 方形色块 + 项目 key（12px/600）+ **会话句柄**（见 §2.3，11px 等宽灰）+ 右侧 `Sessions N` 切换钮 |
| 整栏 | **5% 项目色洗**（`color-mix(... 5%, var(--panel))`）——余光可辨 |
| 输入面 | 输入框 focus 边框与发送按钮 hover 取项目色（当前动作也带项目身份） |
| 消息级 | 保留 `chat-project-tag` 的每条消息 chip（不动） |

**验收口径**：切换项目时，右栏的**色相**必须变（不是只变文字）；截图对比两项目的带面/带底/洗色三者都要不同；
色盲场景下靠「项目 key 文字 + 句柄」兜底（颜色不是唯一通道）。

### 2.2 会话账册落项目（不再只存 localStorage）

- **真源**：`<projects_root>/<key>/sessions.json`
  ```json
  { "version": 1,
    "sessions": [ { "session_id": "session-09ca0247-…", "handle": "executor", "title": "",
                    "opened_at": 1791080000000, "last_opened_at": 1791092000000,
                    "cwd": "/Users/user/Documents/sandbar" } ] }
  ```
- **localStorage 降级为缓存**：可丢，丢了从项目文件重建（读失败/坏 JSON → 空表，不崩，沿用既有容错纪律）。
- **写路径**：UI → 宿主 API（workbench 宿主侧写项目目录，与 `watchdog.json` / `executor-grants.json` 同族，**宿主专属**；
  执行器可读不可写）。
- **迁移**：首次打开读旧 localStorage 账册，能读到的条目写入项目文件（**同一个 origin 内可迁**）；
  宿主这次丢的那份（旧 `localhost` origin）已经拿不回来——认账，不做考古，只在文件里从这一刻起记全。
- **好处**：换 origin / 换端口 / 重启 console 都不丢；可 `grep`；项目级事实与项目其它账（授权、动作、看板）同处一地。

### 2.3 会话句柄（id 不用数字）：**只有短码，不做短名**

宿主 261004：「感觉不需要短名了」——**采纳**。

| 部分 | 规则 |
| --- | --- |
| **短码** | 会话 uuid 的前 4 位十六进制（`session-09ca0247-…` → `09ca`）；项目内撞码则扩到 6 位。**稳定、可引用** |
| **执行器会话** | 固定名 **`executor`**（本项目固定角色，不带码、不参与登记序号） |
| **`title`** | 用户改名仍可覆盖显示（字段本来就有）；**不自动取名**，不拿第一句话做 slug（猜错比没有更烦） |
| **`seq`** | 只留作历史排序，**不再当引用显示**（宿主：数字当 id 怪） |
| **一致性** | 同一套短码出现在：**左栏会话行 / 右栏 chat 身份带 / 请求账引用（`#a3f2` 同族）/ 票详情** |

**为什么不用纯数字**：数字不带语义、跨项目重复（每个项目都有 1 号）、当引用会歧义（「第 3 个会话」得先问哪个项目）。

### 2.4 项目身份＝**颜色 + 特殊形状 + 结构**（宿主 261004：「颜色可以再多一些，或者加一个形状」→「形状要特别一点，避免圆点方块之类」）

**先说避坑**：常见的 `圆点 / 方块 / 三角 / 菱形 / 胶囊` **一律不用**——它们和界面里已有的
状态点、复选框、警告符、列表符号、按钮同形，会读出错误语义（宿主原话：「容易和其他 ui 上的元素产生歧义」）。

**定稿三通道**：

| 通道 | 取值 | 作用 |
| --- | --- | --- |
| **颜色** | **12 色**（色相 30° 一档，亮度带锁 l≈0.66 保暗底可读） | 第一眼的主通道 |
| **轮廓**（非常见形） | `pentagon`（平顶五边）/ `hexagon`（尖顶六边）/ `octagon`（八边）/ `shield`（盾）/ `sparkle`（四角星）/ `tag`（切角标签） | 灰度/色觉障碍下仍可分；形状本身就是「项目徽标」的语义，不像任何控件 |
| **结构** | `solid`（实心）/ `ring`（空心环，mask 挖洞）/ `half`（同色 55% 打底 + 右半 100%，明暗双色） | 同一轮廓再多三态；`half` 在灰度下也分得开 |

⇒ **12 × 6 × 3 = 216 种身份**；分配仍按「两个哈希流取首选对 + 在已知项目集上去重」，
`projects.yaml` 可声明 `color`/`shape` 覆盖。

**mock 里的三例**（可切项目实时看，灰度截图也验过）：
`sandbar = 空心五边形`、`suyou = 实心四角星`、`nusuyou = 双色盾`。

**尺寸**：左栏项目行 14px、会话行 11px、chat 身份带 13px——11px 下空心环的内孔仍有约 5px，
不糊；`sparkle` 这类细尖形在小尺寸下退化为实心（不画洞）。

### 2.5 左栏也要能一眼分项目（宿主 261004）

- **项目行**：名称前一枚 **14px 徽标**（色 + 形），比现在的 8px 色点显眼；项目块**左侧 3px 项目色条**；
  当前选中的项目块再叠一层 **6% 项目色洗**——多项目同屏时，块的边界一眼可辨；
- **会话行**（每项目一条）：**11px 徽标** + 句柄短码 + `open` 按钮；
- 工单行不加色（左栏已经够花）：工单的归属靠「它在哪个项目块里 + 行第二行的 epic 链接」。

### 2.6 怎么新建一个项目会话（宿主 261004 追问）

> 措辞更正（261004，宿主确认）：这里说的是**项目会话**（有项目上下文、登记在本项目的会话账册里），
> 不是"全局会话"。全局会话不属本期范围。

**两个入口**（都在项目上下文里，不会建到别的项目）：

1. **左栏 → 项目块 → 会话区 → `+ New session`**（虚线行，最常用）；
2. **右栏 chat 身份带的 `Sessions N` 菜单 → 底部 `+ New session`**（在当前 chat 里就地新建）。

**新建之后的规则**：

| 项 | 口径 |
| --- | --- |
| **落点** | 新会话的 `cwd` = **该项目主目录**（一开口就带项目上下文） |
| **登记** | 写进 `<projects_root>/<key>/sessions.json`：`session_id` + **短码** + `opened_at`；MRU 排最前 |
| **界面** | 右栏**立刻切到新会话**（身份带换短码；**颜色与形状不变**——还是同一个项目） |
| **列表** | 左栏会话区列出本项目所有会话（含 `executor` 那条）；chat 带的 `Sessions N` 菜单是同一份列表 + `+ New session` |
| **不改授权** | `+ New session` 建的是**普通项目会话**；**「谁是执行器」由 Grants 页的 `executor_sessions` 声明决定**，新建会话不会自动获得执行器身份（会话数量 ≠ 授权面） |
| **不做删除** | 本期不做删除/关闭（会话是宿主的资源）；侧栏只列「你打开/新建过的」（账册口径不变，磁盘存量不进列表） |

**为什么放这两处**：新建会话永远发生在「某个项目的上下文里」——左栏是选项目的自然位置，
右栏身份带是「我正看着这个项目的 chat、想开一条新的」的自然位置；两处都会把新会话直接打开，
不要求用户再去别处找。
