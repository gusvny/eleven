# 261004 并发上限（Running tickets）设计稿

> 状态：**草稿，等宿主过 mock**（`notes/discussions/261004-concurrency-limit-mock.html`，v1）。
> 宿主令原话：「今天你要『控制并发』，实际可用的手段只有人肉暂停 + 不再派新票。要不要开票把上限
> 做成声明（例如「同时非终态泳道 ≤ N，超了排队」——这个我想做成 project 级别的，在 executor panel
> 上可以配置。就在 overview 上加吧。做个 mock 我看看。」

## 1. 为什么要有它（261004 实测）

- **引擎里没有这个旋钮**：查过 `activities.py` / `agent_activities.py` / dispatch 面，只有闸内并发
  （`SANDBAR_HANDOVER_CONC`、场景并发 12），**没有「同时在跑的泳道 ≤ N」**。
- 今天同时开过 **7 条泳道**，代价是实打实的：verify_lane 的 pytest 段 5.5 分钟/轮，两条时序敏感
  测试（`test_d2b_carrier_…`、`browser-state.test.mjs` 的 detail-scroll）在负载下随机红，
  还可能被误读成「实现段 code-fault」（KI-182/184 同族：机器噪声污染放行口径）。
- 现有的控制手段只有**人肉**：暂停（**段间生效**——在飞的段会跑完）+ 不再派新票。前者不精确，
  后者靠人盯。

## 2. 形态：两块一对（宿主 261004 二次裁定后改的）

> 宿主两次口径：先要「Overview 上加」，看过 v1/v2 后说 **「过于 informative」**（点名：后果句、队列明细、
> FIFO 说明、折叠说明都不要）；再补 **「我们左栏已经有工单列表了，可以在左栏调优先级，左栏工单列表的 ui
> 一起调整」**。所以上限与顺序**分居两处**，各司其职。

### 2.1 右栏（执行器面板 Overview）：**只管上限**，一行

```
RUNNING TICKETS  [AT THE LIMIT]                        set by you 10-04 14:02
┌──────────────────────────────────────────────────────────────────────────┐
│ Limit  [−] 3 [+]  ·  3 at work  ·  4 waiting                    [Save]   │
└──────────────────────────────────────────────────────────────────────────┘
```

- 状态 chip 三态：`room to start one` / `at the limit` / `over the limit`（琥珀）；
- **界面上不解释、不列队列、不放折叠说明**——口径写进本文档，不写进界面（宿主要求）；
- 审计行（谁在何时改的）保留在区块头右侧，一个短语。

### 2.2 左栏（控制台）：**项目列表 + 展开那个项目的工单列表**（管顺序）

- 左栏顶层是**项目**（`sandbar` / `suyou` / `nusuyou`…），每行右侧给该项目的两个数
  （`3 at work · 4 waiting`）；**展开的那个项目**才显示它的工单列表（一次展开一个，点项目行切换）；
- **上限与队列都是项目级的**：切项目 = 换一套上限与队列（右栏 Overview 跟着切）；
- 多项目同时在跑时，**机器总负载 = 各项目在跑数之和**（本设计不设机器级上限，见 §6 未决）。

#### 单项目内的工单列表（管顺序）

- 每行两行制：**第一行 = 票号 + 标题**（给足宽度），**第二行 = 阶段**（小字等宽）；
- **排队中的票**行首带**位次号**（1、2、3…），并可**拖动**（⋮⋮ 把手）或用 **⌃ / ⌄** 调序；
- **在跑的票**行首是**绿点**、**你暂停的票**是**琥珀点**——它们**不参与排序**（无把手、无箭头）；
- 列表头只报两个数：`3 at work · 4 waiting`（不写句子）；
- 一行版式决定：左栏 380px 宽（340px 下标题被截得太狠）。

## 2.3 两块怎么配合

**左栏的顺序 = 谁下一个开跑；右栏的上限 = 同时最多几个在跑**。额度一释放（有票完成/失败/转人门/被暂停），
就按左栏顺序从队首取一条开跑。宿主只在一处调顺序、一处调上限，不必记两套规则。

## 2.4 巡检票：epic 归谁、占不占额度（261004 宿主提问）

**现状实测（今天没有规则）**：

- **期票没有 epic**：起票入口 `inspection_ticketing.open_period_ticket` 根本没有 epic 参数，
  巡检声明里也没有 epic 键 ⇒ 每期巡检票都落在「无 epic」那一类；
- **findings 开出来的修码票 epic 乱**：历史样本里有 `inspection`、有 `project-executor`、也有空的
  （`t261003-03` / `t261002-11` / `t261002-14` 都是空的）；
- 建议开票（`suggested_fix_tickets`）**只带证据与建议标题，不带 epic**，谁开谁选。

**建议规则（等宿主拍）**：

1. **期票归它的巡检实例声明的 epic**：声明加一个 `epic:` 键（sandbar 的实例填 `inspection`），
   期票盖这个 epic；本项目要改归属只改声明。
2. **findings 开出的修码票**：先看该发现有没有点名票号（很多发现引用具体票），
   **有就用那张票的 epic**（机械可查），没有就落实例声明的 epic；开票时人仍可改。
3. **期票吃开发票的额度（宿主 261004 裁定：选 b「照吃」）**：期票和别的票一样排队、一样占额度，
   不另给巡检配额。落地时必须带三条口径，否则会出假红：
   - **到点即排队首**：期票到点后**默认排到队首**（下一个有额度就开跑），但不越过额度；
     宿主若不满意，在左栏把它往下拖即可（顺序本来就由你调）。
   - **「排队的期票」≠「漏跑」**：漏跑核查的判据从「台账里有这一期」**扩成**
     「台账里有这一期 **或** 该期票已铸出且未终结」——后者只标 `queued · waiting for a slot`，
     **不报警**（KI-191/192 的教训：判据点名了不存在的动作最要命）。
   - **排久了给低级别提醒**（不是红）：例如等超 6 小时提示一条「期票已排队 6 小时」，
     由你决定是否拖到队首。

## 3. 语义（判据写死，别留给实现各拍）


1. **占额度 = 「在飞」**：当前段正在跑的票 **＋ 等你签字的票**（宿主 261004 裁定：「占着吧」）。
   含义刻意如此：**额度会被人的关口吃掉**，停在 merge 门等你签的票会顶住额度、顶住后续派活——
   这是「逼着处理」的压力，不是 bug。界面上这类票用**琥珀实心点**标出，行内第二行写明
   `merge · awaiting your signature`。
2. **不占额度**：**你主动暂停的票**（空心点）与已终结的票。
3. **超出即排队**：队列 **FIFO**，**顺序由左栏拖动/箭头人工调**（不另做「一键置顶」，宿主 261004 裁定「不要」）；
   票已创建但**首段不得开跑**，直到有额度释放。
4. **下调到低于在跑数：不打断任何在跑段**，只影响下一次启动（面板明写这句，避免以为会杀活）。
5. **额度的每个终态都要销账**：完成 / 失败 / 被暂停 / 转人门 / 取消——凡占过额度的，每个终态都要放回去
   （资源生命周期纪律：否则额度会「泄漏」，表现为永远排不上队）。
6. **上限取值 = 1 到 10 的整数，再往上是不限**（宿主 261004 裁定「范围扩大到不限」）：界面上
   `[−] N [+]` 连点到底显示 `Unlimited`（chip 显示 `no limit`），从不限按 `−` 回到 10。默认 **3**。
   为什么默认 3：实测 3 条在跑时闸的墙钟与抖动都正常，**5–7 条开始出机器噪声**（时序测试随机红）。

## 4. 落点与审计

- 声明落在**本项目自己的声明文件**里（机器级项目目录，宿主直管；与 `executor-grants.json`、
  `watchdog.json` 同族），**不写进受保护的仓内配置**。
- 每次改动入项目动作账（谁、何时、从几改到几），面板显示最近一次改动；与授权面同一纪律
  （`by` 不可由调用方自填——KI-193 的教训）。

## 5. 引擎侧要什么（真正的工程量在这）

1. **一个「排队」态**：票创建后不等于立刻开工；派活/启动侧在开跑前判额度，不够就排队（不是先跑再暂停——
   段间暂停拦不住首段）。
2. **额度释放的触发面**：段结束、票终结、票转人门、被暂停——每处都要销账（见 §3.5）。
3. **可见性**：排队位次与已等时长要能被面板读到（面板只读账，不自己算）。
4. **与既有暂停的关系**：被暂停的票自动不占额度（不需要额外动作）。

## 6. 已拍（261004 宿主六条）与唯一未决

**已拍**：

1. **等你签字的票占额度**（「占着吧」）——额度被人的关口吃掉＝逼着处理；界面上琥珀实心点标出。
2. **不做「一键置顶」**（「不要」）——顺序只靠左栏拖动/箭头。
3. **下调不打断在跑的段**（「可以」）——只影响下一次启动。
4. **范围扩到「不限」**（「范围扩大到不限」）——1…10 → `Unlimited`，默认 3。
5. **不加机器级上限**（「先不要」）——多项目并行时总负载是各项目之和，这条留作以后。

**唯一未决**：**巡检期票的 epic 归属与配额**（见 §2.4）——期票归实例声明的 epic 我没意见，
要你定的是第 3 条：期票**吃不吃**开发票的额度（我推荐：不吃，给巡检一个很小的独立配额，
并把「排队的期票不算漏跑」写成显式口径）。

## 7. 入口归并：控制台原有的那些入口怎么办（261004 宿主提问）

**现状（读代码）**：左栏每个项目一行，行上入口图标簇＝**常驻两枚 `Tickets`（board）/ `Epics`**，
另有 **`Docs` / `Model Routes` / `Project Settings`** 三枚收在 `⋯ More views` 里；
项目组头下还有**项目内会话区**（会话行 + 新建）；顶栏有 **Temporal UI 外链 / workers / Inspection 报告**；
侧栏底部有 **Metrics**；中列是执行器视图，**Open session 按钮在面板 Overview 的 strip 里**。

**设计原则**：**一个项目 = 一列工单（左栏）+ 一个驾驶舱（执行器面板）+ 两个只读资料面**。
入口只保留这三类，其余全部归并——同一件事不该有两个入口、两套口径。

| 旧入口 | 去向 | 理由 |
| --- | --- | --- |
| `Tickets`（board 图标） | **左栏工单列表本身**（点项目行即展开；该枚图标保留为「回到工单视图」的常亮位） | 工单列表就是左栏主视图，图标只作定位 |
| `Epics` | **常驻图标保留** | 只读资料面；也是工单列表按 epic 过滤的入口 |
| **Executor（驾驶舱）** | **新增第三枚常驻图标**（本设计新增） | 面板是项目的控制面，必须一键可达 |
| `Docs` | 收进 `⋯`（只读资料面） | 读面，不必常驻 |
| `Model Routes` | **归并进面板的 `Settings`** | 它是**配置**不是视图；今天仓内那份陈旧副本已误导过一次，配置只该有一处 |
| `Project Settings` | **归并进面板的 `Settings`** | 同上 |
| 顶栏 `Inspection`（报告按钮） | **归并进面板的 `Inspection` tab**；顶栏只留一个数字（待裁 N），点了跳该 tab | 巡检已经是面板的一个 tab，两处查看=两套口径 |
| 项目内会话区 / `Open session` | **会话区留在左栏项目组头下**；`Open session` **留在面板 Overview 的 strip** | 会话是项目的资源，驾驶舱负责开它 |
| 顶栏 `workers` / `Temporal UI` / 侧栏 `Metrics` | **保留在机器级**（不分项目） | 跨项目的运维/观测面，不属任何单项目 |
| lane map / problems / closed ledger | **留在工单列表页内**（过滤与抽屉） | 它们是工单列表的筛选维度，不另设入口 |

### 7.1 点这些图标 / 点一行票，分别发生什么（261004 宿主追问）

**图标 = 主区视图开关**；**左栏始终不变**（项目 + 该项目工单列表 + 队列顺序）。

| 点什么 | 主区变成 | 细节 |
| --- | --- | --- |
| **▤ 工单** | **工单板**（Ticket Board） | 卡片式全量列表：状态左条 + `阶段 · epic` + 迷你进度条；顶部三个过滤 `All / Queued / In flight`；**点任一卡 → 右侧抽屉** |
| **◆ 立项单** | **立项单列表** | 每条：代号 + 状态 + 票数 + 一个 `Filter the list`（把左栏过滤到该 epic）；点代号 → 打开立项单正文（只读渲染） |
| **▶ 驾驶舱** | **执行器面板** | Overview / Grants / Alerts / Ledger / Inspection / Settings 六个 tab |
| **⋯** | **读面与去向** | `Docs` 直接打开；`Model routes` 与 `Project settings` 显示「已并入面板 Settings」并给一个跳转 |

**点一行票（左栏或工单板都算）→ 右侧抽屉**（覆盖式，不挤走主区）：
票号 + 标题 + 四个动作（`Sign` / `Send back` / `Retry check` / `Pause`）+ 字段（项目 / epic / 阶段 / 状态）
+ **十段进展脊柱**（已完成绿点、当前蓝点）+ 「变更、时间线、回执在此」。关掉抽屉即回到原视图。

**左栏列表与主区工单板的分工**（避免以为是重复入口）：
左栏 = **队列视图**（两行制、为**调顺序**而生，只列本项目、永远在视野里）；
主区 = **全板视图**（为**看与批**而生，带过滤与卡片细节）。
同一份数据，两种用途。

**净结果**：每项目常驻三枚（`工单 / 立项单 / 驾驶舱`）+ 一枚 `⋯`（`Docs`）；
配置类（模型路由、项目设置）收进驾驶舱的 `Settings`；机器级三样（workers / Temporal / Metrics）留在全局。
需要宿主确认的只有一句：**把模型路由与项目设置这两枚从侧栏摘掉、并进面板 `Settings`**，你认吗？
