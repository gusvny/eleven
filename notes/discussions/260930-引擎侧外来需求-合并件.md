## 二、按族详述

### 族 A：静默放行（最危险——让不该过的东西过闸）

**F01（N④）实施段删子用例＝绿漂移** 实案 `t260929-14`：验收面看起来全绿，仲裁判 `code-fault`——
「DEF-1 入口崩被**删子用例掩盖**；该子用例已恢复并复现红」。**这是唯一能让"票面全绿而带病上线"的入口**，
与业务内容无关。我核过：sandbar 引擎与 `integration/lint_tests.py` 都**没有**"子用例数不得减少/
断言不得放宽"的机械判据。
→ 修法：仲裁段加一条**纯机械判据**——实施段对**设计段场景文件**的差集：**子用例数不得减少、
断言不得放宽**（逐子用例点名，删子用例即红）。判据住 `shared`（纯函数，可单测），取证面=设计段
交付物 vs 实施段交付物的 AST/文本子用例清单差集。

**F02（E2 + N⑦）交接命令面** 两处同族（都在 `run_handover_legs` 这条链上）：
- **E2 误判**：`_handover_conc()` 缺省 **4**（docstring 明写"移交命令彼此独立"），而"发布/安装
  + 校验其产物"天然有序 ⇒ 校验对着**发布前**状态判 ⇒ `t260929-20` 闸报「15 跑 7 过 8 败」而
  交付全绿（把关人逐条手跑 12/12 `exit 0`；产物落地时刻在闸窗口最末尾）。
- **N⑦ 语法坏照旧放行**：`t260929-38` 交接命令带字面 `cd <lane_root> && …`（`<` 是重定向）⇒
  18/18 解析期即死、**零执行**，却按契约"不进主口径"**不拦票**——"一条都没跑"与"跑了但红"
  长得一样。
→ 修法（一条链上一起治）：①**非零退出条目串行复核一次**，报告以复核为准（保留提速、消灭
误判；真红仍红）；②入账前 `sh -n` 类**语法自检**，不过即拒收并点名；③回执把
**未执行／语法坏／执行红**分三态具名；④"可直接在泳道根执行"这句契约由**收单侧机械校验**。

### 族 B：坏态不可恢复（票/历史被搞坏，且查不到）

**F04（E4 + N⑧）终态票的清场留痕与收口**
- E4：`t260929-31` 被终结为 TERMINATED，历史理由串写着"宿主经…当面决定停掉本票"，而**该决定
  从未发生**（该票唯一的信号是 `pause`）。正规路径必先 `cancel_notice`（信号先入历史、失败即
  不终结）；本次历史里**没有 notice**。引擎侧确有一条裸 `handle.terminate`（`client.py`）。
  **他们的未查明项很关键**：`admin.log` 里**没有任何 cancel 记录** ⇒ 极可能不是引擎任何入口，
  而是**引擎之外**直接 terminate（脚本/别的会话）。
- N⑧：终态 FAILED 票 `cancel`/`close_out` **回执逐字同款幂等无功**（无归档/收口语义），且
  `audit_write_failed: Operation not permitted: …/sandbar/server/admin.log`——收口理由没落审计。
→ 修法：①引擎两条 terminate 路径**机械追加发起方署名**（`by=<identity>`，不做文本匹配——
让"宿主决定"这种人话与署名并列摆在历史里，冒充一眼可辨）；②新增**只读检测面**：终止/失败票
**缺 `cancel_notice` 留痕 ⇒ 具名上报**（这是外挂 terminate 唯一的可检形态）；③终态票的
**归档/收口语义**（从活动列表移出、理由可查、历史不删）；④审计写失败继续 fail-loud（已在回执点名）。

**F05（E5）终态票不可查** 对终态票 `show` 得"快照不可得"（源码注释表明**有意**如此），于是
查清 E4 只能自己写 Temporal SDK 脚本读 history。
→ 修法：`show`/UI 详情面加**终态回落**：终结/失败事件类型 + **理由串** + 最后一个信号名。
（F04 的检测面要能被看见，前提就是这条。）

**F12（N⑥）已闭环** `rework to_stage=<引擎推荐的别名>` ⇒ `ValueError: 未知阶段 ''` ⇒ 工作流
任务永久失败、票不可查、不可恢复（nusuyou `t260929-28` 作废）。已修 `ab3a817`：相位兜底
（空串/未知/done 一律夹到合法值+留痕）、主循环尾 `raise`→`blocked`、拒收提示只推可执行相位。

### 族 C：回执/报告面失真（丢信息或造信息）

**F03（N①）回执超尺寸 ⇒ 终态** `t260929-11` 落盘闸拒收 14750 项，拒收名单全列进回执 ⇒
`received message larger than max (4546900 vs 4194304)` ⇒ 活动无法完成 ⇒ 重试耗尽 ⇒ **终态
FAILED**。本该"打回重跑"能救的票变成作废。
→ 修法：①拒收信息**截断**（只报计数＋前 N 条＋完整清单落文件）；②大目录拒收走 `blocked`
（可 retry/rework），**不走终态**；③与 F02 同族：交接/拒收回执都该有"尺寸上界 + 上界具名"。

**F06（E6 + N②）报告面把人引偏**
- E6：KI-049 红灯「写集刷新被拒：回执 files_changed 为空数组…**处置：rework 回 create_plan**」
  一天 4 次，**四次都不需要 rework**（写集零污染、票自己跑完）⇒ 噪音 + 处方诱发空转。
- N②：`t260929-14` 在 create_plan↔review_plan 空转 4 轮，复审说"方案 byte 相同重投"、开发说
  "`.sandbar/` 只有第 1 轮复审"——**两边都对，病在送达**（复审原文没随重派送到）。
→ 修法：①E6 两态区分（"有改动但回执空" vs "确实无改动"）+ **去掉会诱发空转的处方**；②N②
**引擎显式把"最近一次复审结果原文"注入重派 prompt**（现在只有 rework note 进 `previous_context`）
+ "重投产物与上一版 byte 相同 ⇒ 段内拦下并点名'复审未送达'"。（②的后半是判据面新增，需宿主定口径。）

**F11（E1）已闭环 + 一处 runbook 更正** 活动侧文案精确（`_result_gone_detail`），但
`format_agent_stage_failure` 只取最外层 `ActivityError`（"Activity task failed"）⇒ 票面等于没说。
已由 t260929-18 / `a0fe537` 修（沿 `.cause` 链追加根因；只改文案不改控制流 + 配套测试）。
**待改**：引擎给的处置是"挪走坏档留证后发 retry_qc"，而实测**只发 retry_qc 就自愈**（重跑落到
新一代文件名，agent 的"文件在场=已完成"幂等锚点自然失效）⇒ 文案改两步：**先单发 retry_qc；
同类失败在同一文件名上复现再挪档**（挪档要动泳道工作区，能不动就不动）。

### 族 D：能力/契约面（要宿主定，不属"顺手修"）

**F07（E3）写集不可改、授权管不了写集** `t260929-31` 写集漏了一个注册面文件 ⇒ 写集闸回滚 ⇒
该票 L1 注册面**永久一红**；车道提示"升级宿主扩界"**没有可执行入口**（`update` 无写集字段；
`AUTH_KINDS` 只有 `protected_path`/`arbitration_verdict`，`path_gates.py` 完全不消费授权）。
白跑约 40 分钟 + 作废重开。
→ 半直修 + 半决策：**(a) 说清**（create 回执与帮助文本写明"写集建票后不可改；`authorize` 放不开
写集"）；**(b) 是否允许 `update` 追加写集（只许加不许删）＋留审计**＝能力与安全面取舍，**宿主定**；
(c)「新增命令/接口」类票的**注册面清单提示**属项目侧知识，建议由项目声明注入而非引擎写死。

**F08（N⑨ + N③）契约与判据的单一真源**
- N⑨a：lane 段契约要求定点复跑用 `python3 integration/run_scenarios.py --only <场景名>`，而**项目侧
  执行器的唯一 argv 入口只认 `--print-pool-assets`**（`--only` 静默忽略 ⇒ 退化成整轮全量 ⇒ 要么
  白烧、要么被"禁第二趟全量"护栏判红）。**注：sandbar 自己的执行器支持 `--only`** ⇒ 这是
  「通用契约绑了单个项目的能力」，不是项目侧违规。
- N⑨b：引擎契约门（`cs_machine_qc contract`）与项目自检各写一套判据 ⇒ **自证绿、门外红**
  （古籍票自检 22719 项全绿；门外报三组红 2560/1509/3）。
- N③：content-studio 发布段**只对账不落地** ⇒ 声明 `contract_hold` 的票恒卡（模板在项目侧）。
→ 修法（建议）：①契约里的复跑命令**由项目声明注入**（或写明"以项目声明为准"）；②manifest
schema＋判据做成**可导入单点**（门提供 `--schema`），回执**同时给"自检结论 vs 门结论"**并显性
点名差异面；③发布段与落地段的职责边界由**模板**明确（缺落地承接时引擎应出可见发现）。

**F09（N⑤）lane 供给面不全** 只盖部分写集的泳道里没有成员仓/依赖 ⇒ 依赖这些输入的场景**必红**，
"存量红"一词因此被滥用。项目侧已自建 `SKIP` 协议（打 `SKIP [名] prereq absent: … (registered:
<票号>)` 并 exit 0，不产红、随 `output_tail` 落账可核）。
→ 取舍：**lane provisioning 按需补齐**（重、但红少） vs **统一"输入结构性缺席"表达**（轻、但要
引擎给一个统一具名面）。**宿主定**；nusuyou 的 SKIP 形态可直接作为引擎侧统一面的候选。

**F10（E7）`cancel` 判据未程序化** 文档写"判据（全部满足才 cancel）① blocked ② retry_qc 复现
③ 无在飞价值"，程序侧只校验 `who`/`reason` 非空 ⇒ 运行中的票也能被终结。
→ 三选一（宿主定）：**默认强制**（非 blocked 拒收 + 显式 `force` 旗，破例留痕）／**只改口径**
（把"判据"改成"建议"并注明程序不拦）／**两者都做**（默认强制 + 文档同步）。我倾向"默认强制 +
`force` 留痕"——清场是逃生门，得留，但要留痕。
