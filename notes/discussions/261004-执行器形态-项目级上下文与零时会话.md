# 261004 执行器形态：项目级上下文 + 常驻「决策会话」（可轮换）+ 每事件零时会话

> 来源：261004 与宿主逐轮过稿。宿主原话要点：「是不是应该有个项目级的上下文，其实 events 和
> 我们在做的 recent actions 就是上下文，每次有新事件了就开个新 session，做完了关掉」「常驻的
> 会话也要能够轮换（防上下文爆炸、防被 block）」「太多会话的问题，这些其实都是零时会话，
> 用完了可以删掉吗」。
>
> 本页是草稿账本条目（notes 属草稿纸）。定稿迁 `docs/`（设计稿，只写「是什么、为什么」）。

## 1. 为什么要改（实测问题，不是设想）

1. **单常驻会话的上下文一直在涨**：`session-09ca0247` 已 82 轮 / 784 条助手消息；消息类内容
   **9.8 M 字符**（粗估 3.3–4.9 M tokens），其中 **82%（8.06 M 字符）是它自己写的报告与表格**。
   它那条会话自己的 `request/context` 记录声明 `contextWindow = 1,000,000` tokens。这个构建里
   找不到 compaction / trim 的证据 ⇒ 「是否已超窗、谁来裁」**未确认**（要 harness 侧回答）。
2. **长活会卡住整条线**：普通唤醒排队（`wakeMode = redline ? steer : queue`），只有红线能打断；
   而停摆判据只看「会话时间戳前进」（`sessionProgress = advanced`）、**不看 `running` 位**
   ⇒ 长回合（在跑、只是暂时没落消息）会被误判停摆（假告警），也可能反过来掩盖真卡死。
3. **没有冗余**：它是单会话，一忙全项目没人推进。
4. **会话存储已经在长胖**：sandbar 项目下 **70 个会话目录 / 188 MB**（全机 81 个）；今天**没有**
   任何删除工具——控制台那个 Close 明确写着「session content is not deleted」。

## 2. 目标形态

- **项目级上下文 = 三本账 + 声明**：事件账（发生了什么）+ 请求账（人在等什么/答了什么）+
  **动作账**（执行器做了什么、凭哪条权限、哪个会话）+ 授权与守望者声明。
  **纪律：判断力必须落盘，不进会话脑子。**
- **常驻「决策会话」**：只与人对话、做取舍、发指令；**可轮换**。
- **每事件「零时会话」**：醒来 → 读账面（+ 少量现查）→ 执行**一个有界单元** → 结果落盘 → 退出。
- **项目级串行保底**：一次只放一个零时会话上场（先简单；以后需要再按对象细分）。

## 3. 触发器面（不是所有活都是「账本新行」）

账本迁移（含 `blocked` / `refused` / `awaiting-human` 决策态）；宿主答了一条请求；授权声明变化；
守望者告警（停摆 / 自锁 / 对账不一致 / 引擎不在线）；宿主在对话面直接下指令。

## 4. 常驻会话的轮换

- **触发**：上下文量（transcript 字节或轮次）、年龄、被卡住之后、宿主手动。
- **三处要一起动**：面板的授权声明（**现在只能填一个会话**）、`watchdog.json.executor_session`
  （唤醒目标）、以及**交接面**。引擎侧本来就允许多达 8 个被点名会话；以项目目录为 cwd 起的
  会话天然按执行器受闸（cwd 通道），所以身份不必逐个点名，但**动作账必须记会话 id**。
- **必须外部驱动**：会话被 block 时不可能自己轮换 ⇒ 轮换归守望者（检测到停摆/被卡超阈值 →
  起新会话 → 交接 → 退休旧的）。
- **交接必须落盘**（新会话没有记忆）：一页「现在什么状态 / 哪些在办 / 哪些在等宿主」，
  由三本账拼出来。

## 5. 零时会话的删除与归档

**可以删，但三条前提缺一不可：**

1. **先退休再删**：活着/正在写的会话不能删（进程还在追加、控制台持有锁）——需要「未在跑 +
   单元已结清」的判据。
2. **动作账先记全**：删掉 transcript 就没了「当时跑了哪些命令、怎么想的」。**取舍待定**：
   接受「要点在账、细节不留」，还是删前先落一份摘要。
3. **被引用的不删**：`watchdog.json.executor_session`、授权声明里的 `executor_sessions`、
   请求账里**未答请求的 owner**、动作账里的 session 字段——引用先失效或改写。

**工具**：照工单 `ticket-prune` 的样子做会话 prune（默认 dry-run；判据=已结清 + 未在跑 +
无引用；先归档后删）。

**保留规则（待定）**：零时会话保留 N 天；**轮换出去的常驻会话保留**（它同时是对话史与审计）。

## 6. 与现状对比

| | 单常驻（现状） | 决策会话 + 每事件零时会话 |
|---|---|---|
| 上下文 | 一直涨（已 9.8 M 字符） | 每个会话都小 |
| 长活卡住 | 整条线停 | 只卡那一个事件 |
| 并发 | 天然串行 | 要加锁（项目级单飞保底） |
| 人的对话面 | 就是它 | 仍要有常驻那个 |
| 项目记忆 | 它脑子里 | **必须全部落盘** |

## 7. 待宿主拍的四件（**261004 收官时仍未拍**，列在这里不做保留；等宿主下一次决定）

2. 删除零时会话前是否留摘要（建议：留一页要点）；
3. 零时会话保留几天；
4. 串行粒度：项目级单飞，还是按对象（票/红/请求）细分。
