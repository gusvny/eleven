# 讨论档：写集改革——白名单执法 → 黑名单+分层（260904，integration 代笔待宿主过稿）

> 缘起：宿主质询 260904——「写集，天天都是写集问题，为啥我们需要写集呢」
> 「smoke 这种目录，默认为啥不开呢」「要考虑多项目的时候，别的项目的情况可能是不同的」。

## 一、病根：写集在干三份工作，其中两份不该它干

1. **意图声明**（计划面）：review_plan 审「打算改哪些文件」——承诺，天然是预测；
2. **执法**（警察面）：verify_lane 拿白名单逐行判 diff，写集外一笔不许落；
3. **闸路由**（分类面）：「是不是 UI 票、要不要截图」按声明判定。

病全部出在**拿预测去执法**——工作本身会发现新范围，预测必然漂移：

| 病历 | 型 | 实证 |
| --- | --- | --- |
| KI-021 | 声明**冻结** | 开票时刻预测，票中现实扩张，无修订通道 |
| KI-044（已修） | 声明**过粗** | 整目录声明绕过 UI 闸（修复=判定已换实际 diff，本改革第一块落地） |
| t260904-11 死锁→KI-047 | 声明**过窄** | 写集外过时守卫 dev 不能修，只能等并 main，而消解回路又被 verify 红压制 |
| KI-011 | **填错** | 建单方三连犯，预测从源头歪 |
| KI-015 | 判定**机械坑** | 半截路径假红、裁剪吞文件名 |

## 二、模型：三层（执法真源只有一个=实际 diff）

| 层 | 例子 | 规则 |
| --- | --- | --- |
| **黑名单（永闭）** | `notes/`（台账 main 直管）、`.dsh/`、`profiles/`、机器级路径 | 硬闸。小而稳定——真正必须永守的禁区，几乎不变 |
| **验证资产（默认开）** | tests/、smoke/、scenarios、守卫 | 不需预声明。理由：守卫与行为强耦合（预测哪个守卫要动=预测范围，同类不可能）；改坏自红（自检，爆炸半径小）；守卫过时不许动比被跟修更危险（07/11 双实证）。**改动=审读必审项**：「对齐事实 vs 挪门柱」——agent 弱化守卫自绿的诚信风险由审读兜，不由封死兜 |
| **产品代码（声明面）** | src/、lib/、引擎 py | 开票声明（保留：review_plan 审承诺面+并行泳道排程预测冲突——今天 08/09/13 串行决策的正确用法）。**漂移=黄牌需解释**：diff 出现声明外产品文件不自动红，交付时必须解释；有理由过、无理由拒 |

守卫改动必审项与 UI 证据闸同构（KI-044 模式）：按实际 diff 判定、高亮进审读、不预防性封死。

## 三、多项目维度（宿主质询定稿方向）

**三层清单是每项目的声明物，不是引擎全局硬编码。** 各项目布局不同：

- 纯文档项目：无验证资产层，`docs/` 本身就是声明面；
- 有生成物目录的项目：`build/`、`dist/` 可设「默认开+漂移豁免」（机器产物非人审对象）；
- 结构迥异的项目：守卫目录不叫 smoke/tests，黑名单有独有禁区（如产品密钥目录）。

落地形态⚑待拍板，候选：

- **A（推荐）**：项目根 `verify.yaml` 并列增 `lane-policy.yaml`（或并节）——verify.yaml 已是每项目声明物先例（test 道声明），装载器 Python/TS 双侧同源纪律沿用；
- B：塞进注册表 `~/.sandbar/projects/<key>/project.yaml`——不推荐（严格最小 YAML 子集，塞策略破坏「写坏即隔离」的窄面设计）。

路径口径：清单内路径**相对项目根**解析（KI-032 锚定闸同源——project_root 锚定后相对路径才有意义）。缺省策略=引擎内置 default（sandbar dogfood 值），项目未声明按缺省走，声明了按并集/覆盖语义⚑。

## 四、迁移面（引擎改动清单，随立项拆票）

1. `ticket-start`：`write_set` 语义改 advisory（改名 intent_set 或保留字段改文档口径）；
2. `verify_lane`：白名单执法→黑名单执法+漂移报告（声明外产品文件=黄牌进回执非红灯）；
3. `merge_check`：漂移黄牌进 check 项；验证资产改动触发「守卫对齐 vs 挪门柱」必审项；
4. 审读模板（acceptance/merge 人门）：守卫改动必审项+漂移解释核对项；
5. KI-047 顺治：mixed-red 排序——verify 红可被 merge 治愈时不再压制消解回路（或：消解回路前置）。

## 五、⚑ 待拍板清单

1. 政策文件位置（verify.yaml 并列 lane-policy.yaml vs 其他）；
2. 漂移解释载体（结果文件字段 vs 交付注记 vs 签字 note）；
3. 黑名单缺省值定稿（notes/.dsh/profiles 之外还有什么进缺省）；
4. 覆盖语义（项目声明与引擎缺省：并集 or 显式全量替换）；
5. 过渡期口径（在飞票按旧规走完，新票即新规？）。

## 六、Nongoal

- 不动 UI 证据闸方向（已换 diff 源，本改革只推广其模式）；
- 不做角色级权限系统（黑名单是路径级，不按 agent 身份分权）；
- 不动 lane 泳道物理机制（worktree/分支/squash 照旧）。
