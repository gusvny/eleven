## 2 逐页一句话

1. 封面 —— 只有标题 *Sandbar* 与副题 *An exploration towards Software Factory*。
   （原来那句一句定义与「人守两端」小字，按宿主 261011 令已删；
   定义改由第 4 页标题「Engineering IDE of AI era」与第 6 页的正式定义页承担。）
   封面**带一条开场备注**（宿主 261011 令，按 `N` 显示）：先问台下「你们相信几年后我们还会手写代码吗」，等他们答；再讲自己的痛——今天我成了三四个 agent 的调度器、每天早上重新拼上下文的人、因为没人可托付判断所以什么都得自己审的人；会话蒸发、工作没有主人、编码变快只是把瓶颈挪到了我身上。这份痛就是做这个项目的原因。
2. **为什么做 Sandbar** —— 左：五条症状（人肉调度、聊天记录不是工程状态、看不见工程、
   验证没跟上、能力租在外面）；右：通用 harness 只回答「怎么执行」，企业要回答
   「做什么、怎么算做完」，缺的三样是持久流程状态、客观完成判定、组织级记账。
   外部证据：Anthropic 费马项目引入 Prove2Me 后不到两周约 1300 万行 Lean 证明。
   收尾一句：放大器不产生组织者
3. **Sandbar 自己开发自己** —— 自举用 Claude Code（GLM-5.3）做了几天，之后全靠自己；
   左栏人机分工；右栏三个角色的模型；页脚：298/1,086 个提交动了引擎本身、479 张票在这一个月里结项
4. **一个月的记录** —— 窗口固定 **2026-09-10 → 2026-10-10（31 天）**：
   1,086 commits / 519,736 行（文本文件，不含生成物与二进制）/ 2,139 个文件；
   行数构成：测试 340,697、产品 151,995、文档 27,044；**测试对产品 = 2.2 : 1**；
   右半边小图是这 31 天每天的提交数（合计 1,086 次，平均 35 次/天，峰值 10-09 的 157 次，
   只有 09-12 一天没有提交）。行数与文件数取窗口结束那一刻的仓库状态
5. **Engineering IDE of AI era**（高层架构图）—— 页标题照写 *Engineering IDE of AI era*；
   副标题按宿主 261011 令**已删**（「上一代 IDE 给一个工程师一张台子、这一代给一支 agent 队伍」
   那句话只在讲稿里，不上屏）。图自上而下：**人** → **SANDBAR 方框**（内含
   **控制台 console** 与六项领域资产：工单工作图 / spec / 闸门 / 验证资产 / 知识库 / 审计；
   框内下方一行底注 *RUNS ON · open-source foundation — we run it, we did not write it*，
   下面并排 **PROCESS ENGINE（Temporal）** 与 **AGENT RUNTIME（dsh）**）→ 框外最下面是
   **模型**（按角色路由、随时可换）。
   **宿主 261011 两处修正**：① 控制台、流程引擎、agent 运行时都画进 sandbar 框内
   （框内那行底注说明这两块是开源地基、不是我们写的）；② 原「工作区 worktree/账本」
   一块已删，不再上屏。
6. **上下文怎么分层管**（How the context is managed）—— 六层从上到下：
   **TRUTH · docs/**（只放验证过的事实：设计、术语、手册；入口 docs/README.md，机器索引 docs/index.json）
   → **DRAFTS · notes/**（讨论稿、立项、缺陷台账；**agent 不读它**，只有在验证事件发生时毕业进 docs/，
   图上用虚线框加一支向上的箭头）→ **INTENT · spec**（方向级=立项单，任务级=票面：做什么、为什么、
   怎么算好、能改哪些文件）→ **THE JOB · work graph**（一票一条持久流程：工位、依赖、边界；
   agent 读的是票，不是聊天记录）→ **HANDOVERS · artifacts**（方案、测试设计、闸门结果、结果文件，
   逐站落盘交接，不靠记忆）→ **SESSION · the agent**（agent 自己的上下文：按票划范围、独立工作区，
   随时可以消失，活不会消失）。收尾：可信度来自结构——哪个目录、哪个索引、哪道闸，不靠求模型自己甄别。
7. **完成由证据判定**（Done is decided by evidence）—— 三段证据阶梯，各带一个标签：
   **MACHINE-CHECKABLE**（标签 script）：构建、单测、集成、回归守卫、性能、合并预演——
   机器能判的绝不交给模型；**INDEPENDENT JUDGEMENT**（agent）：另一个角色审方案、设计测试、
   仲裁、验收走查——产出的人永远不给自己判卷；**HUMAN SIGNATURE**（human，主色描边）：
   人读的是一页证据加关键 diff，不是两千行代码，理由进不可变历史——不签字，流程就停在那里。
   底部两行规则：闸门不过就打回；红必须具名（产品红／环境红／别人的红）；禁止重跑到绿；
   每修一个缺陷就变成一条永久守卫——「什么算对」的标准在长。
   收尾：结论出自裁判，不出自选手。
8. **可扩展性**（Extensibility）—— 五行扩展点，每行写明「你要写的东西」与实例：
   **THE CHAIN**（写一个模板模块）：项目自带工位链，运行时加载——实例 nusuyou 八段链 + 两道人门；
   **THE ROLES**（写一个角色文件）：角色是声明——规矩、红线、交接物；实例 developer / integration /
   product-operation；**THE MODELS**（写一张路由表）：按角色、按分工、按账号——不改代码，
   实例「构建角色走 GLM-5.3-flash、执行器走 mimo」；**THE PROJECTS**（写一份声明文件）：
   注册一个项目就是写一份文件，别的都不用动，实例「三个项目同一套引擎」；
   **THE SURFACE**（写一个插件）：控制台是微内核上的插件，不是单体——工单台、签字、度量、
   守望者、provider、知识库。图下一行：流程里没有任何东西是写死的。收尾：扩展 sandbar =
   写声明，不是 fork 引擎。
9. **五层杠杆** —— 人的杠杆、成果持久、并行规模化（一个月 479 张票结项）、用证据替代逐行评审、可度量
10. **诚实的分界** —— 左：已实证（三个项目、一个月 479 张票结项、无人值守、崩溃恢复、自举、回归钉死）；
    右：待测量（编排时间、并行曲线、模型替代 A/B、评审负载、跨域）；
    最大风险：工作图拆错了，错得还很高效——两道人门可拦
11. **下一步：我们想做的四件事** —— ① **在更多项目上验证**（今天只跑我们自己三个项目，
    要拿到 eBay 的项目上去证明这套模式不挑项目）；② **离开本机、上云**（今天引擎、流程引擎、
    面板全跑在一台机器上，接下来容器化 + 多租户）；③ **多人协作**（今天一张票一个人签字，
    要让多人在同一块板上分工签字、各有各的审计）；④ **决策模型进关口**（像 Jev 这类
    不生成文字、只给「选哪个 + 把握多大」的模型，适合判红分流与路由；一句话带过，
    并说明先拿自己的判红记录做对照、赢了才进关口，不要引用厂商的宣传数字）。
    另加一条横条「Sharpening the verification layer」：**Google Mantis**（9 月开源的漏洞发现/定级/
    修复 harness，做法是把发现按目录与仓库分层归并，并要求**修复必须在沙箱里被复现验证**）、
    **open-code-review** 这类 AI 评审工具，以及**变异测试（Cosmic Ray、MutPy）**——
    用来反问「我们这些测试，真的抓得住被塞进去的缺陷吗」；
    口径是「只采纳在自己的度量里赢的那些」。
    这两样不是新架构，是「证据链 + 上下文交接」同类做法的校准（Mantis 自报省 85% token，
    是厂商数字，别当结论讲）。
    收尾诉求：继续投入 · 一个真实业务域 · 一个团队

## 3 诚实口径（必须守）

1. **跨模型校验现在没生效** —— developer 与 integration 用的是同一个模型、同一个账号
   （260915 临时宿主令）。被问起就答：靠角色分离、工位隔离和关口，不靠模型交叉。
2. **「完全依赖 AI 写代码」要改口径** —— 说「所有代码都经由工单、由 AI 执行落地」，
   不要说「每个 commit 都来自 AI」（主干侧还有文档与登记类提交）。
3. **行数不含生成代码** —— 页面上报的 519,736 行是自己写的三块（测试/产品/文档）；
   打包产物、vendor、压缩文件共 40,099 行不计入，页脚写明了。
4. **第 3 页的模型表** —— integration 显示 glm-5.3，是按宿主 261010 要求写的；
   生效路由表里实际是 glm-5.3-flash。台下若有人对表，口径答「GLM-5.3 这一档」。

## 4 放映纪律

1. 屏幕上的字是断言，不是名词。
2. 数字只留几个：1,086 commits（或 31 天）、2.2 : 1、479 张票、268 条已知问题。
3. 术语换外行词：lane → workspace、写集 → write scope、打回 → sent back、闸 → gate。
4. 现场演示要有兜底：控制台要登录，演示前别拿同一台机器跑重活；
   若现场加载失败，退回幻灯片里的截图与数字。
5. **配色两套**：默认浅色（投影与打印都清楚），按 `T` 切深色（暗房间更舒服）；
   浏览器会记住选择。PDF 导出的是浅色那套。
6. **放映无需讲稿**：幻灯片不带备注；本文件可另存一份自用，别投在屏幕上。
