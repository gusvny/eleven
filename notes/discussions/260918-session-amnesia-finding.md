# 260918：agent 会话"失忆重跑"——全板拖慢的头号原因（事实与证据）

**性质**：观测/机制缺口，非某张票的缺陷。本稿只写事实、证据与影响面，**不含方案**（口径待宿主定）。
**取证时间**：2026-09-18 14:48（本地）；取证方式=全只读（读日志、数计数、看票面），未改任何代码或票面。

---

## 一、事实（一条命令可复现）

统计在案 5 张票**当天**（09-18，按文件 mtime 过滤）的 `agent_*.log`：

| 票 | 今日 agent 日志份数 | 会话「回落新建」次数 | 会话「坏帧」次数 |
|---|---|---|---|
| t260917-08 | 35 | **34** | 50 |
| t260916-25 | 25 | **23** | 38 |
| t260917-05 | 13 | **23** | 34 |
| t260916-26 | 12 | **19** | 36 |
| t260917-09 | 20 | **16** | 30 |
| **合计** | 105 | **115** | **188** |

口径：
- 「回落新建」= 日志行 `恢复会话 <票>-<角色> 失败（回落新建同 id 会话）`
- 「坏帧」= 同一行的失败原因含 `corrupt Zstandard session log…` 或 `corrupt session log: first line is not a session header`
- 复现命令（只读）：
  ```
  for f in .lane/<票>/.sandbar/agent_*.log; do
    grep -c '回落新建同 id 会话' "$f"; grep -c 'corrupt ' "$f"; done
  ```

## 二、含义（用一句话说）

`t260917-08` 今天起了 35 份 agent 日志，**其中 34 次是"恢复不了上一次会话、于是从零新建"**——
**agent 几乎每次重跑都是失忆的**：上一轮已经查过的东西、已经写过的结论、已经对过的断言，
它拿不到，只能重新做一遍。同一张票、同一个阶段（验收走查/仲裁）于是反复重做。

## 三、机制（读码所得，供判读）

- 引擎每个阶段派活时用**确定性会话 id**（`<票>-<角色>`，如 `t260916-25-acceptance`）去续跑，
  指望 agent 接着上一次的上下文继续；
- 运行体（dsh headless）在该 id 的会话文件**缺失或损坏**时，**不阻断**，而是
  **回落新建一个同名空会话**把活干下去——票面/阶段状态看不出差别；
- 于是「续跑」在事实上变成「从零重跑」，而票面显示的仍是"第 N 次进入本段"，看起来像正常迭代。

## 四、影响面（为什么值得优先）

1. **速度**：每轮重跑都要把上一轮的侦察/验证重做一遍——5 张票今天合计 115 次失忆重跑；
2. **轮次被吃满**：每轮都计入「测试集迭代」额度，撞满上限就触发"转人工判读"的假封
   （260917 夜 t260916-19/-21/-04 三票实证一致）；
3. **审计面失真**：票面只有"进入本步（第 N 次）"，看不出这一轮的 agent 是否失忆——
   昨晚 5 张票卡了 8 小时，票面上几乎看不出来；
4. **无票认领**：在案 5 张里没有一张在治这条；`t260917-08` 治的是"会话面零静默降级"的
   另一个面（存在会话文件但格式对不上时要响亮），**与本条（恢复失败静默重建）相邻但不同**。
