## 1. 为什么要改（今天的实测）

1. **agent 审查范围塌陷**：261003 期 integration-tests 面的 `scope_files = 1`、agent 发现 **0** 条；
   而 261001 / 261002 期是 **13 / 9** 个文件、给出 **6 / 4** 条真代码缺陷（`shared.py` 两个同名
   `__getattr__` 互相遮蔽、`code_stamp` 惰性化后语义变化、语言闸 CJK 正则窄于声明等）。
   塌陷的原因写在报告自己身上：「本期无泳道基点 → 取当前 HEAD 自播种」——**基点链断了**。
2. **公共扫描跨面重复**：261003 期两张巡检票的泳道/守望者扫描行 **9 条逐字相同**（simplify 12 条
   发现里 9 条不是它自己的主题）。
3. **环境红占满报警预算**：15 条 high 里 8 条是 `ENV_FAIL`；套件里 38 条环境红，根因是 chromium
   缺失 + 测试台端口口径不一致。
4. **快照过期**：泳道类发现等人签字等了 **7.5 小时**，签字时 t261002-13/14 早已关闭。
5. **出口只有人门**：两张票都停在 `close` 人门，签了才闭环。

## 2. 两面共用第一步：先把「上期基点之后变了什么」算出来

- 输入：上期巡检报告的基点（`base_head` / 账本水位）→ 本期差集。
- 硬前提：**基点必须真实**。无基点时**回退上期报告的基点**，**不许自播种当前 HEAD**
  （自播种 = 差分消失 = 本期等于没审）。
- 输出：本期**新工单清单** + 本期**改动文件清单**（按 `integration/`、`server/` 等分面切）。
- 自检：差集过小（例如新增用例 0、改动文件 < 阈值）时，报告**首页显式点名「本期没什么可审」**，
  不许静默成「没问题」。

## 3. 测试面：五步（贵的那一步挪到最后）

| 步 | 做什么 | 输入 | 输出 |
|---|---|---|---|
| T1 | **本期跑了哪些新工单** | 上期基点后的事件账本新行 + 看板 | 新工单清单（含各自当前段/状态） |
| T2 | **这些工单新加了哪些用例** | 那些票在 `integration/` 里新增/改动的场景文件（git 差分） | 新用例清单（文件 + 注册表条目） |
| T3 | **这些用例写得合不合理** | agent 审查，**范围 = T2 那批**（天然有界） | 逐条发现：哪条用例、违反哪条判据、证据行号 |
| T4 | **这些工单里用例跑得怎么样** | **每张泳道票自己跑过的回执**（`<泳道>/out/integration-report-*.json`、票面 `results.run_integration_tests.evidence`）——**不重跑** | 逐票结论：跑没跑成、红在哪、环境红还是代码红 |
| T5 | **整体跑一遍扫漏** | 完整套件（今天这一跑约 2 小时） | 只用于「跨票/跨用例的遗漏」，不重复 T4 的逐票结论 |

- T3 判据引用现成的 `docs/testing-guide.md`：intent 与高层步骤齐、灰盒「绑定浅」、不重复意图、
  不锚实现细节、夹具不得自证（照实现假设塑形的夹具）。
- T4 的边界：某票**没跑成**（卡环境红等）必须**显式点名原因**，不许跳过；**环境红不算发现**，
  只记「未跑」。
- T5 的边界：环境不就绪 = **显式「未跑」**，绝不拿环境红当发现。

## 4. 简化面：四步（新代码在前，全库分片在后）

| 步 | 做什么 | 输入 | 输出 |
|---|---|---|---|
| S1 | **本期新写了什么代码** | 第 2 节的改动文件清单 | 新代码清单（按模块） |
| S2 | **这些新代码合不合理** | agent 审查，范围 = S1 | 逐条发现：哪一行、违反哪条判据、可观测风险 |
| S3 | **全库看一遍有没有可优化** | **两层手段**：① **机械面每期全量**（lint / 规则 / 编译 / 跨语言清单锁 / 禁词守卫——扫 20 MB 只要几秒）；② **agent 深读两层触发**：**每期按「最久没审过」审一片**（40–60 个文件 ≈ 20–30 万 token），**全库深读改为按需**（宿主随时点一次，不列入每期例行） | 该片发现 + **本期覆盖清单**（审了哪些、没审哪些） |

- **「最久没审过」怎么算**：需要一本**审查台账**（每文件一条「上次被审的期号/时间」）。每期从台账里取最久未审的 40–60 个文件，审完写回；**按需的全库深读也写同一本台账**，否则下一次切片会重复审同一批。
- **按需全库**的形态（待定项见 §7）：由人触发一次专门的巡检实例（可以点名范围），产出同样进报告与身份去重账，**不占当期例行的预算**。
- **为什么 agent 不能"每期都看全部"**（实测）：全仓受管源码 **1298 个文件 / 20.08 MB ≈ 700 万 token**
  ——是它 1M 上下文窗口的 **7 倍**，光读一遍都不够，更别说审。同一份证据也说明**窄而深 > 宽而浅**：
  74 个文件浅扫出 **2 条**有用发现，9–13 个文件深读出 **4–6 条**。
- 所以"全库"这件事靠两条路径：**机械检查全量**（便宜，必须每期全跑）、**agent 判断切片**（稀缺，必须限范围）。
  想让全库都被 agent 深读，只能改**频次或预算**（见 §7），不能改范围。
| S4 | 汇总 → 去重 → 建议票 → 人门 | 上面的发现 | 报告 + 建议票；每条说得出风险，量控制在「一票能修完」 |

- S2/S3 判据清单（都能在项目里找到出处，逐条核）：
  死代码 / 重复实现 / 单一真源 / 失败要响（不许静默降级）/ 资源生命周期每个终态有回收 /
  报错精确（说清哪个检查失败）/ **照搬既有实现必须列同族清单** / 外部输入查畸形-缺失-迟到三态。
- **纯风格与改名类单独分档或直接丢**：说不清「可观测风险」的不进发现列表（否则全库审查必然变噪声）。
- S3 的覆盖清单是硬要求：**没审的不许算「没问题」**。

## 5. 两面共用的四条纪律

1. **身份去重**：发现的身份 =「规则 + 对象」（如 `lane-stuck:t261002-14`、`suite-red:<场景>`），
   **不许按文案或计数生成**（否则改一个字就算新发现，跨期去重失效）。
2. **公共扫描跨面去重**：泳道/守望者扫描**只落一处**（声明归属），别的面只留一行「另有 N 条，见某处」，
   不计入本面 summary、不生成建议票。
3. **「仍然成立」必须继续可见**：上期报过、本期仍存在的问题要重新出现（标「自某天起持续」），
   不许因为「报过」就消失。
4. **环境红不算 high、不生成建议票**，只作「未跑」显式记录。

## 6. 与现状的差异（三处关键）

- **顺序**：今天「先跑全套 → 再扫」；改成「先看新工单/新代码 → 贵的那一步最后」。
- **agent 审查的范围**：今天审「差分出来的文件」（断了就 1 个文件）；改成审**本期新增的用例/代码**。
- **新增一步**：今天完全不看「那些票自己跑出来的回执」；改成 T4 逐票取现成回执，**不重跑**。

## 7. 巡检入口：执行器面板新增一个 Tab（按需全库在这里触发）——261004 宿主裁定

- **入口位置**：执行器面板新增一个 **Inspection** tab（与 Overview / Grants / Alerts / Ledger / Settings 并列）。
  它只看**本项目**的巡检（面板本来就是项目级面）。
- **tab 里放什么**（待细化，见 §8）：
  1. **本期报告摘要**：各面（test / simplify）的发现数、点名的关键项、**本期覆盖清单**（审了哪些、没审哪些）；
  2. **按需全库的触发**：一个按钮 → 起一次专门的巡检实例；可点名范围（例如只审 `server/plugins`）；
  3. **触发记录**：谁在什么时候触发的、跑完的结论（只读）。
- **触发是写操作，必须记名**：起巡检 = 起一条 workflow。要记「谁触发、什么时候、什么范围」，
  并落进项目自己的账（与动作账同一族）；面板按钮不能是匿名入口。
- **权限（261004 裁定）**：**执行器不能触发**——按需全库是**宿主专属**。按钮只在宿主操作面，文案要写明
  （"Only you can start a full review. The executor cannot."）。
- **台账落点（261004 裁定）**：放**项目目录**。建议 `~/.sandbar/projects/<key>/inspection/reviewed.jsonl`
  （追加式，一行一个文件 + 上次被审的期号/时间）。**丢了就丢了，重来**——按"全部未审"重排，不报错、不做复杂自愈。
- **按需全库的形态（261004 裁定）**：可点名范围（例如只审 `server/plugins`）；触发必须填**理由**（进记录）；
  结果落一份独立记录，并**写同一本台账**。
- 面板侧要遵守既有的面板约定：列表契约（来源/排序/条数/空态）、STE 文案、跟随控制台主题——
  见 `t261004-14` 与 `docs/reference/writing-standard.md`。
- **视觉基准**：`notes/discussions/261004-inspection-tab-mock.html`（宿主过目后落盘）。
- **版式约定（261004 宿主实报「对齐和留空不好」后定）**：**一条文字槽位**——卡片内文字、区块标题、
  说明行、表格首列、指标键名共用同一个左沿（`--gx`）；容器（卡片/期号/按钮）外沿另算一条；
  垂直方向用一套节奏（区块间距 / 卡片间距 / 行间距三级，别各写各的）；**右沿也要对齐**
  （卡片内右对齐的 meta、表格末列、工具条按钮落在同一条线）；指标用**等宽网格**而不是挤成一排。
  验收方式：用 Range 量**文字实际起点**，各元素左沿差 ≤1px、右沿同线；
  带内边距的控件（按钮、工单号芯片）只对齐**盒子外沿**，其内部文字缩进不算不齐。
  实测（1280 宽视口，261004 mock v5）：文字左沿 40/41 一条线；容器外沿一条线（卡片 26↔1254）；
  卡内右对齐文字 1239，表格末列工单芯片的**盒右沿**同线，芯片文字与「无票破折号」同一条内缩线（1234）。
  同一条规则要喂给面板实现：宽度一改，验收量的就是「组内同一条线」，不是固定像素值。
- **页面留白：面板要用满窗口，不许两边空一大片（261004 宿主实报）**：实测线上面板 `.wrap{max-width:900px}`
  在 1600 宽窗口里两边各空 350px（44% 是白边），Overview 两栏各只有 426px——长请求读起来很费劲。
  定：页面宽度随窗口（例如 `max-width:min(1440px,100%)` + `padding:0 clamp(16px,2vw,28px)`），
  1600 宽下左右留白 ≤5%；**可读性靠内容自身的行长上限，不靠把页面变窄**。
  mock 同步改（v5）。
- **「发现数」与「点名项」是两个东西，文案必须分开写（261004 mock 自审后定）**：上面两张面卡给的是
  **计数**（high/med/low 之和），下面的表是**点名的关键项**——两张数不相等是正常的，不是漏行。
  因此区块标题用「Named findings」，说明行写「4 named of 16 counted」，并给出该期报告的入口
  （`Open the <period> report`），让「剩下的去哪看」有去处。早期 mock 用「Findings / Showing 4 of 16」
  会被读成「表漏了 12 行」。
- **没报告的期要合并成一项（261004 宿主裁定）**：连着好几期都没报告时，期号条不许挂一长串
  「(no report)」——**连续的「无报告期」合并成一项**：标签写跨度与条数
  （`20261001–20260928 · 4 without a report`），点进去**逐期分述因由**（差集过小 / 归档缺失各写各的，
  **合并不等于抹掉差异**）。只有一期无报告时仍各自成项（标签 `(no report)`）。
  「相邻即连续」的前提是**期号序列本身连续**（缺期也显式占位），所以合并只按列表相邻判断，不做日期算术。
  边界：本期自己无报告时也被并进去，标签保留 `(this period)`；说明行按有没有报告分开写
  （`These periods are closed. Shown read-only from the archive.` / `This period is closed. There is no report to show.`），
  不拿一句通用话糊过去。基线见 mock v6。
- **巡检 tab 按「面/实例」组织，文档面也是一张卡（261004 宿主令「doc 的巡检也要放到 ui 上」）**：
  一期之下**每个巡检实例一张面卡**（integration-tests = Integration tests、simplify = Simplify、
  docs-sync = **Documents**），卡片字段与实例节奏无关地统一：强度计数（high/med/low）、
  本期覆盖、一期报告入口。三个实例节奏不同（每天 07:30 / 每天 09:30 / **周一 10:00**），
  所以必须能表达「**这个实例本期没跑**」而不是「没有发现」：卡上写
  `No report for this period. The document instance runs weekly (Mondays 10:00). Last report X; next run Y.`
- **文档面的计分位（只有它有）**：`documents read`（**全量**，例 `78 of 78`）、
  `must-check list`（本期**代码变化面**点名要校的文档数，例 `6 docs`）、`gaps`
  （变了的关键面**没有任何页面**提到）；说明行分述三类篇数（`normative 9 · history 17 · notes 60`）
  与本期分片数（`read in full this period (2 shards)`）。
- **覆盖度两行、两种口径，必须分开写**：代码是**切片**（`Code: 60 of 1298 source files reviewed`），
  文档是**全量**（`Documents: 78 of 78 read in full · whole library, not a slice`，条走满）。
  本期文档面没跑时**不许写「0 of 0」**——写 `no report this period (weekly instance)` + 上次报告期号。
- **覆盖度是滚动窗口，范围可选（261004 宿主令「Coverage 是不是应该能选个时间 range，比如看 7 天的」）**：
  覆盖度不是「本期快照」，而是**滚动窗口**：`this period / 7 days / 30 days / all`（**默认 7 天**），
  三行分开写——①**代码**（窗口内审过多少 / 总数，切片口径）；②**文档**（窗口内读了多少次 / 总数，
  全量口径）；③**队列**（多少文件从没审过、最久等了几天；这是**当前状态，不随范围变**，所以行上标
  `current state`）。「this period」这一档跟随期号选择；文档面那天没跑就如实写 `0 of 78`，
  不许写成「没问题」。
  数据源＝项目目录里的**被审台账**（一行一个文件 + 期号/时间，丢了就重来）——正因为它逐行记时间，
  任意范围才算得出来。**这一块存在的理由**：没有窗口视图，永远看不出切片轮读有没有真的在推进、
  队列是在缩短还是在原地打转。基线见 mock v8。
> **文档面（doc face）的判据、范围、机械层与未决项单独立稿**：
> `notes/discussions/261004-文档面巡检-设计稿.md`（261004；机械层复活已获宿主批准，票未开）。
> 下两条只保留与本页（tab/节奏/覆盖度）相关的部分。

- **文档面每天跑（261004 宿主令「doc 每天跑也行的」）**：声明从「每周一 10:00」改**每天 10:00**
  （与 07:30 全量集成、09:30 simplify 错开），并加 `skip_when_unchanged=true`
  ——整仓一点没动的那天只落一行裁决（`skipped-no-change`），不重读内容完全相同的文档；
  有动静就**全量读**。文档库体量（docs 25 篇 + notes 60 篇 ≈ 40 万 token）支持天天全量，
  这是它和代码面（700 万 token 只能切片轮读）的根本差别。
- **每张面卡自带该实例本期的报告入口**：三个实例各写各的期台账
  （`out/inspection/inspection-<实例>-<期号>.json`），所以报告不是整期一份，而是**一面一份**；
  期级只留一个「本期摘要」入口。
- **按需全库的范围下拉补一项**：`docs/ + notes/ only (85 documents)`（宿主专属不变，
  执行器不能触发）——文档面既要按期自动跑，也要能被点名单独跑一次。
- **空态文案（写死在契约里，别等实现各写各的）**：
  本期无报告 → 「No report for this period.」（下一行写因由，例：The change set was too small.）；
  合并项 → 「No report for these periods.」+ 逐期一行的因由表；
  归档缺期 → 「The report is not available for this period.」；没触发过任何按需巡检 → 「No reviews started yet.」；
  某期两面都零发现 → 「No findings this period.」（不是空白）。
