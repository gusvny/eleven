# 测试层级与 e2e 准入（草稿）

> 来源：宿主 261004 追问——「什么东西应该写 e2e，什么不应该，这个是不是要说清楚，不要搞出一堆 e2e
> 浪费时间，巡检的时候也要检查。」
> 现状实据（我数的）：注册场景 **494** 条，其中 **贵场景 95 条（19%）**——`engine` 60、`exclusive` 24、
> `browser` 11；其余 `ro` 241 + `ro/serial` 60 + `browser-free` 40 等属便宜档。整套墙钟 **8–12 分钟**
> （实测 487s / 518s / 708s 等）。
> 背景实例：一个字段在面板保存时被静默丢弃——它本该由**一条静态平价检查 + 一条 0.07 秒的契约用例**
> 拦住，而不是由 e2e 拦住。

## 一、四层（这是事实分层，不是我新造的）

| 层 | 谁交付 | 形态 | 单位成本 |
| --- | --- | --- | --- |
| **L0 静态/机械** | 任何角色 | lint / 平价检查 / 源码锁 / 锚点清单 | 毫秒（全仓一轮 ~15 秒） |
| **L1 单元** | developer（随本票） | 纯函数与模块电池（pytest / node） | 毫秒 |
| **L2 组件契约** | integration | 组件对外契约的灰盒断言：离线、无浏览器、无台 | 毫秒–秒 |
| **L3 系统场景（e2e）** | integration | 组装态上跑一条旅程或注入一次故障 | 单条 0.5–12 分钟；整套 8–12 分钟 |

## 二、什么时候**才**能写 e2e（逐条成立才行）

1. **跨组件缝**：要验的性质无法由任何单一组件的契约表达（例：**"你答了请求，执行器会被唤醒"**——跨面板、守望者、引擎、会话接口）。
2. **或**只有组装态才可达的故障模式（例：docker 台组装失败、**撕裂挂载**、会话恢复的残缺态、端口/锁争用）。
3. **或****用户旅程本身**（宿主按顺序点、等、看的那种）。
4. **便宜层做不到**：L0/L1/L2 都表达不了它。**凡是能被静态检查或毫秒级契约用例抓住的，禁止写 e2e。**
5. **值得每次合并都付**：它守的是一个真实的回归类，不是一次性事件。
6. **必须具名**：intent 里写清"为什么不能是 L1/L2"、它属于哪个池（成本档）、锚点（L16 已有）。

## 三、禁止（写了就是错）

1. **字段 / 校验 / 解析 / 往返**类性质 → L1 或 L2。（今天那个面板保存丢字段就是这一类。）
2. **UI 渲染 / 排序 / 文案 / 格式化** → L2 的浏览器无关契约。**只有性质本身是浏览器行为**（滚动位置、真实布局、真实点击）才用浏览器。
3. **静态可判**的（键集合、路径形态、术语、锚点在场） → L0。
4. **与低层 intent 重复**（这条禁则已有）：同一意图已有用例覆盖时不另起。
5. **为了"覆盖率好看"**把低层已经断言过的东西在组装态再跑一遍。
6. 用一条贵场景去钉一个**一次性 bug**——应当把它沉淀成**便宜的那层**。

## 四、预算（防"一堆 e2e"）

1. **每票新增 e2e ≤ 1 条**；第 2 条必须写明"为什么不能合并进第 1 条 / 为什么不能降层"。
2. **优先参数化已有场景**（加子用例），而不是新注册一条——顺带少一次共享注册表冲突。
3. **贵池（`engine` / `browser` / `exclusive`）**每票要有净增理由；说不出理由就降池。
4. **趋势看守**：整套墙钟超阈值（暂定 >10 分钟）或贵场景数净增，**必须在巡检报告里出现**，不许静默。

## 五、执法（三处，缺一不可）

1. **L0 机械（每次合并）**：lint 加一条——**贵池场景**的 intent 必须带**分层理由标记**与**成本档**；
   没有即红（具名到场景）。便宜、可机械判，正好治"随手加一条"。
2. **评审清单**：`docs/reference/code-review-checklist.md` 加一行——新增贵场景是否给了分层理由与成本档。
3. **巡检**（宿主点名要的）：
   - 判定项 A：本期新增/改动的场景里，有没有**可以降层**的（离线、确定性、无跨缝）→ 出**降层建议**；
   - 判定项 B：整套墙钟与贵场景数的**趋势**；
   - 判定项 C：有没有与低层 intent **重复**的新场景。

## 六、存量（不追溯，但给候选）

- 现在 95 条贵场景**先只标不拆**。
- 巡检第一期给一份"**可降层候选**"清单（离线且确定性那批）。
- 真要清理时单独立票，不顺手做——否则又是"做一个票发现另一个问题"。
