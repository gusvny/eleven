## ⓪ 说人话版（一分钟）

现在每张票都要自己跑一遍**全量集成套件**（一轮 445 条、约 35 分钟），所以**车队一忙就堵在跑测试上**，而且**一条红能让所有人停手**。

缓冲流把它换掉：**车道只证明自己那一票（本票场景 + 一个很小的快集），内容自动落到"缓冲线"上；全量套件改成按期为整条线跑一次**（变更触发 + 定时兜底）；跑绿了，**一批内容一次人签就进 main**。

于是：**每票成本从"35 分钟"降到"几分钟"**，而重证明**一份内容只做一次**。

## 一、目标（收录口径）

1. **车道不再为每次尝试付一次全量套件**；重证明按"照修订跑一次、谁都在同一份上"来做。
2. **票的命止于缓冲线**：落地 → 等覆盖它的那次认证 → 认证绿即结束；**人的审查移到"批"上**。
3. **红有界**：同一修订先重跑一次，再按车道结果过滤、再二分；**红牵涉到某次落地**走**补救票**（不走打回）。
4. **红期间停止该线落地**，但**已认证前缀永远可落地**——红不许把已经证明过的部分扣为人质。
5. **全量套件在一处共享的串行资源上跑**（它有可预测的成本，也是吞吐的上限）。
6. **一批一次人签**，含代签与授权来源；批与票的出处三段可读（落在哪、被哪次认证覆盖、进没进 main）。
7. **新旧并存**：老流程不动、照样服务在跑的票；新流只作为**可选的新泳道版本**出现，老流程的退役靠**度量**说话。

## 二、范围外（明确不做，直到有真实需求）

- **不做多线**（按 epic／component／仓分线）：门已经留着（记录能装"一组仓修订"、线是声明不是分支名），但**第一期只做单线**。
- **不做仓关系声明与跨仓协调落地**：留作以后，只保证记录不把单仓写死。
- **不做把票钉在机器上 / 多机共享 store**：设计已写（pin、迁移、单一写者），**本期不建**。
- **不改老流程任何门的语义**：新规则只对新泳道版本的票生效。
- **不为了通过测试改集成测试**：证明面有问题就记缺陷，不改判据去迁就。

## 三、分期与已开票

**Phase 0（先把尺子做准）**——缓冲流的全部正当性是一个关于时间的断言，尺子不准，任何决定都是观点。

- **T0.1 run 记录**：跑批头记录（id／修订集／套件／env／宽度／池／时长／计数／verdict）+ 用例行带 `run`；**零执行不算证明**在这条记录上落地。
- **T0.2 度量修准**：环境红不得标成自因失败（`t261008-36` 实证）；`lint_tests.py` 同一输入两个相反结论要有定论。
- **T0.3 快集**：从既有场景清单选成员 + 声明时间预算 + 可跑入口 + **实测耗时与命中**（它是"车道不再跑全量"的效率来源本身）。
  **T0.3 排在 T0.1 之后开**：两者都要改 `integration/run_scenarios.py`，而且 T0.3 的耗时读数要靠 T0.1 的 run 记录。

**Phase 1（单线的最小可用）**：线的声明与自动落地 → 认证驱动 → 冻结与等待 → 推进（promotion，一次人签）→ 票结局投影 → **唯一那扇快修口**（必须早于认证驱动上线）。

**Phase 2**：关系账（`repairs`／源自发现）、**撤回即票** + 推进期"不许把已撤补丁带回来"的机检、巡检在新流下的调整。

**Phase 3**：多线、仓关系、机器钉住、多写者共享——**只保证门开着**。

## 四、判据（这一单算不算成）

1. **每票成本下降可测**：同一批票在新旧流下的落地前耗时对比（不是感觉，是记录里的数）。
2. **一份内容的重证明只做一次**：同一修订的认证不因票多而重复。
3. **红不扣人质**：红存在时，已认证前缀仍能推进。
4. **零执行永不读成绿**：`ran: 0` 在任何面上都不是通过。
5. **老流程可回退**：把票从新版本移回老版本不需要改记录、不需要重编号。
