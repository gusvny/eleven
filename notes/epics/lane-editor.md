## 〇 说人话版（一分钟）

给在飞的工单开一个**能自己动手的窗口**：暂停一下 → 在工单台里打开这张票的工作副本（文件树 + 编辑器 + diff）→ 手工精调代码 → 存盘并留一笔「这是人改的」提交 → 交还，agent 接着往下走。
有些项目必须手工细调，现在人只能签字/打回/说话，**下不去手**——工作副本在泳道里，只有 agent 能写。

## 一 问题（现状事实）

- 泳道 = 一个独立工作副本（git worktree + `lane/<票号>` 分支），agent 在其中改代码；
- **人的介入通道只有三条**：签字（门）、打回（指针回拨）、裁决注入（说话）——**没有"直接改文件"的通道**；
- 人若要改，只能自己在本地 checkout、手工同步、再祈祷不撞 agent 的下一笔落盘；
- 打回后 agent 面对的是"上一轮改到一半的树"（`rework-visibility` 已登记此痛点）——**同族**：工作副本缺人机协同面。

## 二 目标（MVP）

人在**段间暂停窗口**内进入泳道工作副本，完成「看—改—存—交还」闭环：

1. 入口：工单详情 →「接管编辑」（要求当前段可停/已停在段间门口，未满足则提示先暂停）；
2. 编辑：文件树（本泳道）+ 单文件编辑器（等宽/高亮）+ 底部 diff（对照 main 或对照上一代）；
3. 保存：写进**泳道工作副本**（不是临时副本，agent 用的就是这棵）；
4. 提交：可「提交为人工介入」——署名 who、提交信息带 `[human]` 标记，与 agent 的代次提交可区分；
5. 交还：退出编辑 → 恢复派段；期间若 agent 需要人手（阻塞/等人），提示可见。

## 三 关键设计问题（每条=待拍板）

1. **并发与所有权**：第一版只在**段间暂停窗口**开放编辑（暂停已被 t260908-01 交付为基座），从机制上避免人机同写同文件；"边跑边改"（实时协同）列为后续面，需要文件级占用/租约与冲突提示。
2. **落盘与署名**：泳道 `.git` 是 gitfile 指向主仓，agent 沙箱写不了、由 worker 代落盘；人的编辑由 console 侧进程写盘后，需要**显式的人工提交**（不能让它被 agent 下一笔 settle 顺手裹走，否则审计分不清谁写的）。
3. **写集与越界闸**：agent 受写集白名单约束；人下去手改是否同样受约束？建议**允许但标记**（人是协同者，不是受管对象）：越界改动在票面留痕、合并前提示，不硬拦（否则紧急修 bug 时反被自己的闸堵住）。
4. **红线**：只允许写**本票泳道工作副本**；main 永远只读；票收口/泳道拆除后入口失效；禁产端口/console 3099 红线照旧。
5. **可见性**：编辑面要同时看到"agent 现在在哪一段、上一代改了什么"（素材现成：泳道分支上按代次的提交历史）——与 `rework-visibility` 共用。
6. **权限**：谁能接管？建议第一版=宿主本人（或授权在案的代操作），与人门签字同等级；后续再谈"项目内多角色"。

## 四 与既有能力的关系（不重复造）

| 已有能力 | 本 epic 里的角色 |
| --- | --- |
| 段间暂停（t260908-01 已交付） | 人的编辑窗口（互锁：编辑中不派段） |
| worker 代落盘 | 人工改动的提交通道（需加署名与标记） |
| 宿主裁决注入（KI-053） | 人**说话**给 agent；本 epic＝人**动手**，互补 |
| 右栏 chat | 人与 agent 对话；本 epic＝人与文件直接对话 |
| rework-visibility（草稿） | 反向面：打回时看清来路/选择性回退；与本 epic 共用代次 diff 素材 |

## 五 非目标（第一版不做）

- 不做完整 IDE（无终端、无依赖管理、无调试器、无 LSP）；
- 不做 git 操作 GUI（merge/rebase/stash 一律不在此面）；
- 不做多人实时协同（单接管者）；
- 不做"把人改的代码自动推给 agent 上下文"以外的智能体协同（下一段 prompt 是否注入"人改过哪些文件"=待思考项）。

## 六 验收口径草案（终态优先，依 docs/testing-guide.md）

- **终态**：人在暂停窗口改的文件，**下一段 agent 在树里真的看得到**，且该改动进入人工提交（`[human]`+who 可追）；
- **互锁**：编辑会话进行中不派段；未暂停时不可进入编辑（或提示先暂停）；
- **红线**：全过程 main 工作区零改动（断言）；泳道拆除后入口 404/失效；
- **留痕**：越界（写集外）改动在票面可见；人工提交与 agent 代次提交在 `git log` 上可区分；
- **回收**：退出编辑即释放（无残留锁/无孤儿进程）。

## 七 待思考清单（宿主 260910：还有很多地方要想想）

1. 编辑期间 agent 是否进入"等待人"的显式状态（还是保持暂停态即可）？
2. 人在编辑时，agent 的会话上下文如何得知文件被改（下一段 prompt 注入"人改过哪些文件/行"？）
3. 撤销路径：人的改动怎么撤（逐文件回退 / 整体丢弃 / 与 rework-visibility 的选择性回退合并）？
4. 本地编辑器接力（逃生口）：给出工作副本路径 + "在本机编辑器打开"命令，是否纳入 MVP？
5. 长时编辑的会话/计费：编辑面是否计入 agent 用量（应不计）与工单心跳展示（应显示"人正在编辑"）？
6. 多仓票（`repo_worktrees` 多仓）时编辑面如何呈现逐仓文件树？
7. 与巡检/文档面无关的确认：本 epic 只碰工作副本读写与提交，不碰收口/归档链。

## 八 票序草案（待宿主审后定）

- 票①：暂停窗口 + 只读浏览（文件树/diff）+ 显式"接管"状态机（先能看，风险最低）；
- 票②：写与人工提交（署名、`[human]` 标记、admin.log 审计、越界留痕）；
- 票③：代次 diff 与来路可见（与 rework-visibility 合流）；
- 票④（视需要）：边跑边改（文件级占用/冲突提示）、选区交还 agent、本地编辑器接力。
