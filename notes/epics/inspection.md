## ⓪ 说人话版（一分钟）

请一个**定期上门的质检员**：每周（或每并 20 张票）把整个仓的测试和代码从头
审一遍——测试有没有重复的、过时的、守着旧文档的；代码有没有能更简单的、
死了没人知道的机制。审完出一份「发现清单」，**你人审过了才开票修**——
质检员只动嘴，从不动手。

## 为什么（260904 当天实锤）

1. **死机制无人知**：KI-049——「写集跟随方案」机制自建立以来全史零生效
   （「授权扩展」日志 0 条），直到绊倒 11/15/12 三张票才被人肉发现；
2. **测试集在无审查地生长**：118 个场景由几十张票的 agent 各自贡献，已知
   守卫滞后（metrics 契约×4，文档 260904 迁了守卫没跟）；重复/过时断言
   无清单；
3. **补丁层积**：引擎 upsert 补丁、自动消解环、误标翻译层逐层叠加，
   「能不能更简」无人系统性提问。

## 每期巡检＝一张票（260904 宿主问定）

定时器到点**自动开巡检票**（轻量模板：扫→报→人门→收口，无方案/实现重段），
巡检 flow 跑在票里。四重收益：①审计统一（发现/处置/审批全在票史，不发明第二套
记录机制）；②漏审对策白送（巡检票与普通票同老化黄→红）；③**全绿也开票**——
零发现票=心跳证明（dead-man 开关落票史可查）；④修复票引用巡检票号
（来源巡检：<票号>），发现→修复→审批一条链。文档同步 flow 同此原则（每期一票）。
UI：通用渲染器直接吃（一套 UI 裁定），shape=循环+门。

## 骨架（与文档同步 flow 同构，一套 UI 直接吃）

```
触发：周定时（或每并 N 张票）→ 起巡检 flow（integration agent 会话）
  → 三类扫描：
     A 测试面：重复场景（锚点/断言/选择器重叠度）·守卫 vs 文档现实
       （scenario-guard-doc-drift 常驻化）·过时断言（引用行号/文件已挪）
     B 机制面：零调用机制（dead-man 开关泛化——日志/场景全史零命中）
       ·影子代码（写集外补丁层、被绕过的旧路径）
     C 简化面：补丁可退役判定（upsert patch 老化）·重复防御层
       ·过长函数/过深嵌套点名的简化建议（每条带证据+风险注）
  → 产出：发现清单（notes 落账，按严重度分级，每条附证据与建议票面）
  → 人审（UI 巡检行+待审面板，同文档同步 flow 的审阅面）
  → 修：全走 dev-lane 工单（巡检零直接改码——红线）
```

## 边界（红线）

- 巡检**只出报告与开票建议，绝不直接改码**；改一律 dev-lane（带防回退场景）；
- 简化建议必须带「删了会怎样」的风险注+防回退场景验证，人审可毙；
- 频率：周检或按合并计数触发（代码不日腐，别浪费）。
