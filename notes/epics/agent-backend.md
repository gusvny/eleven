## ⓪ 说人话版（一分钟）

现在每张工单里「干活的那个 AI」都由 **dsh** 这一个工具跑。宿主的意思**不是把 dsh 换掉**，而是——

> **让「用哪个执行器」变成每张票可以各选的一个选项**：票 A 用 dsh、票 B 用 codex，**同时各跑各的**。

这比「整体切换」强：①不用赌一次全换（谁好谁坏可以先并行跑着看）；②对照实验变成**日常状态**而不是一次性试验；③哪套不合适当天就能绕开，不会卡住全部工单。

要付出的代价是：**执行器不能是写死的**。我们现在围绕 dsh 建了一整套东西（打回意见回到同一会话、工单台实时看 AI 在干什么、每段结果文件的固定格式、按角色分派模型、我们的工具注册），这些都得**抽象成「接口」＋两套后端**，并且**两套能并存**（同机器同时跑、互不干扰、互不串状态）。

**为什么排在容器化之后**：容器化给了每张票一个干净、隔离的运行环境——这恰好也是「同一台机器上同时跑两种执行器」的前提（各自关在自己的容器里，谁也污染不到谁）。

## 一、问题（现状事实，260913 实核）

**依赖面（代码实测，非估计）**：引擎里 dsh 引用约 **73 处**；与之耦合的能力**六面**：

| 面 | 现状实现 | 换执行器要重建什么 |
| --- | --- | --- |
| 会话延续 | 自研插件 `server/headless-resume/node.ts`，挂 dsh 的 `agents`/`sessions`/`agentDefaultModel` 注入点，按 `ticket-role` 确定性 session id 续接（打回意见进同一会话） | 会话 id 映射与续接语义 |
| 实时可见性 | 工单台 `agent-live.ts` **直接读 dsh 会话私有格式** `<工作区>/.dsh/sessions/…/session.jsonl.zstd`（含对齐 dsh 的 `projectKey()`/`encodeSegment()`） | 流读取适配层（UI 不该再直接读格式） |
| 结果契约 | 各段产出 `stage_*.json`（status/summary/report/deliverables/evidence/files_changed），引擎据此判段成败、写时间线 | 输出 schema + 解析适配 |
| 模型路由 | 经 dsh settings/`agent-default-model` 注入，provider/model 来自我们的 `model-routes.yaml`（按角色分派） | codex 侧路由表与注入 |
| 角色/preset | `sandbar-integration` 等属 dsh preset 体系 | preset 与角色 prompt 围栏重写 |
| 工具面 | 我们的工具（admin.py / verify_lane / capture-lane 等）经 **dsh 工具协议**注册（`sandbox-tools.ts`） | 走 codex 的 MCP/命令约定 |
| （沙箱） | dsh 三层沙箱插件（bash/fs/pwsh）+ permission-presets | codex 自带（含 bwrap/Landlock），且**不受宿主 Seatbelt 之困** |

**codex 侧能力（已核，codex-cli 0.144.6）**：`codex exec`（非交互）、`exec resume`（会话续接）、`-m/--model`、`-p/--profile`、`-s/--sandbox`（三档同 dsh）、`-c key=value` 覆盖、`--output-schema <JSON Schema>`（**让最终响应按我们给的 schema 输出**）、`--skip-git-repo-check`、`-C <dir>`。

**未验（必须在容器里补验）**：codex 在容器内跑 headless 的完整链路（模型调用、工具循环、结果产出）；codex 能否接我们的模型路由（它的默认 provider 是 OpenAI 系，需确认自定 provider 的可行性与形状）。

## 二、目标

1. **执行器可插拔（执行与实现解耦）**：把「起一个 headless agent 干活」抽成一个**边界清晰的执行器接口**，引擎只面向接口编程、**不认识任何具体执行器**；新增执行器＝实现该接口，不改引擎逻辑。
2. **两个后端并存**：`dsh`（现有，逐字节行为不变＝零回归）与 `codex`（新增），**可在同一台机器上同时服务不同工单**；
3. **选择走两级解析（票面 > 项目默认）**：执行器不是「全局开关」，而是**每张票解析一次**：
   - **票面（单票覆盖，唯一的选择落点）**：开票接口加可选参数（如 `executor`），落进票面 meta → **工单台/回执可见、可追溯**；**一票一个执行器、开票时确定、不得中途改**（要换＝新票）。「票 A 用 dsh、票 B 用 codex」就是两张票各自在开票时写一个值——**不需要改任何配置文件**；
   - **项目默认**：模型路由表（机器级真源 `~/.sandbar/projects/<key>/model-routes.yaml`）加 `default_executor`（建议 `dsh`＝零回归）；
   - **解析顺序**：票面（有值即用）→ 项目默认 → 内置 `dsh`。**未配置＝与今天逐字节一致**；
   - **明确不做**（宿主 260913 定，两刀）：①**不做角色级执行器**——票级已能覆盖一切，多一层只会给「两张票为什么不一样」制造第二种解释、把归因搞乱；②**不支持同一张票内不同角色用不同执行器**——一票一个执行器就够了，避免一张票里出现两套会话/两套实时流。工单台可见「本票用的哪个执行器」。
4. **不互串**：两套后端的会话、日志、结果文件、实时流**互不干扰**（同一票永远同一后端；同一角色会话不跨后端复用）。
5. **可度量**：并行跑着的两套，其「哪个更好」有统一指标可读（见下）。
6. **容器内**：两套后端都跑在容器里（前置 ＝ t260913-04），宿主零污染、每票环境自洽；**隔离由容器提供**，不再叠加宿主文件沙箱（见红线 3）。

## 三、执行器接口（面 A 的交付物，先定契约再写实现）

接口只描述**引擎需要什么**，不描述任何执行器怎么做：

| 输入（引擎给） | 输出（执行器回） |
| --- | --- |
| 工作目录（该票的树） | 结果文件（路径由引擎指定，内容按段契约 schema） |
| 角色 + 本段 prompt 全文 | 会话身份（供续接；形状由适配层自持，引擎只当不透明句柄） |
| 结果文件路径 + 段契约 schema | 事件流（供实时可见性；形状由适配层归一） |
| 会话句柄（续接时给） | 退出码/失败原文（供归因） |
| 模型路由（provider/model） | — |
| 环境（容器内已有，含凭据） | — |

**解耦硬要求**：①引擎侧**零执行器分支**（不得出现 `if executor == "codex"`）——差异全部收在适配层与路由表；②执行器接口的实现体不得被引擎直接 import；③新增执行器只需注册，不改引擎任何既有段落；④**回归锁**：`default_executor=dsh` 时，全部 agent 段的命令、patch、会话 id 语义与今天逐字节一致。

## 四、验收/度量口径（**先定口径，再动手**——这是本 epic 的第一步）

**主口径：同一任务双跑**（宿主 260913 定）——把**完全相同的任务**（同一份 prompt、同一 base、同一起始树）**同时发给两个执行器**，各在自己的容器/泳道里跑，比较产出。

| 指标 | 数据来源 | 怎么比 |
| --- | --- | --- |
| 通过与否 | 该任务的验收/测试（如集测段、该票场景） | 第一轮就过 ＝ 1；需打回＝0（并记轮数列） |
| 打回轮次 | `rework` 次数 / `tests-fault` 轮数（Temporal 历史） | 比轮数（越少越好） |
| 产物质量 | 结果文件 + 产物 diff | **盲评**：去掉来源标识，人评（宿主或 integration） |
| 耗时 | 各段墙钟（Temporal 活动历史） | 比中位数 |

**公平性要求**：
- 两条**同期、同 base、同 prompt**；（互补口径，若某类任务不适合双跑，则退回「同类型不同票的平行样本」，每臂 ≥5，最小样本量待宿主定）；
- **双跑期间不插人工干预**（一旦给人给建议，比较即失效；需要指导的轮次单独记「需人工介入次数」，不算通过）；
- 每张票的执行器**记入票面**（可回溯，不靠事后回忆）；
- 报告须含原始数据位置（报告文件、时间线引用、盲评记录）。

## 五、面/票拆解（示意，待审后定票序）

- **面 A（接口与抽象层）**：定义第三节那份执行器接口 + 把现有 dsh 路径收成第一个实现（**行为零变化**）；验收＝`default_executor=dsh` 时全部 agent 段跑法与今天逐字节一致（回归锁）。
- **面 B（执行器解析与声明面）**：两级解析落地——①开票接口加可选 `executor` 参数并落进票面 meta（可查、可追溯、界面可见）；②路由表加 `default_executor`（项目默认）；③解析顺序＝票面 → 项目默认 → 内置 `dsh`；④**一票一执行器、开票即定、不得中途改**（引擎侧校验：票面已定则拒绝任何变更尝试，并给可辨回执）；⑤未配置＝沿用 dsh（零回归）；⑥**不引入角色级配置**（见目标 3 的「明确不做」）。
- **面 C（codex 适配层）**：spawn（`codex exec -C/-s/--skip-git-repo-check`）+ 结果契约（`--output-schema` + 解析；**引擎段解析不动**）+ 会话续接（`exec resume`）+ 模型路由注入 + 工具面（MCP 或命令行约定）+ 实时流归一（UI 用稳定接口，不直接读某家私有格式）。
- **面 D（容器内端到端 + 并存）**：同一台机器上**同时**跑 dsh 票与 codex 票，验证四路不串（会话/日志/结果/实时流）；一张真票的完整一段在容器里用 codex 跑绿（改文件 + 跑该票测试 + worker 代落盘）。
- **面 E（双跑对照与决策）**：按第四节口径出报告；**双跑的两张票就是「开票时各写一个 executor」得到的**（不需改任何配置）；宿主依报告决定后续（长期并存 / 主用其一 / 回退）。

## 六、宿主红线（本 epic 专属）

1. **不得为了让 codex 跑通而放宽任何段契约、断言或判定**（结果契约是引擎判段成败的依据，改它＝动全系统判红口径）；
2. **不得动现有 dsh 路线**：`default_executor=dsh` 时行为必须与今天逐字节一致（对照与共存的前提）；
3. **隔离由容器提供、容器内默认全权**（宿主 260913 定）：容器内**不叠宿主文件沙箱**（关沙箱＝允许 `danger-full-access` / codex 的 `-s danger-full-access`）。**边界从沙箱挪到挂载面**，三条硬条件：
   - ①**挂载面最小化**：每票容器**只挂该票工作区**；依赖树等只读资源**只读挂载**；**绝不挂**宿主主树、`~/.dsh` 全量、其他票的泳道、docker socket；验收须给实证（容器内 `ls /` 只能看到工作区 + 只读依赖）；
   - ②**权限对等**：两套执行器在对比期必须同权限档（都全权或都开沙箱）——**否则双跑比出来的差异可能只是权限差异，结论作废**；
   - ③**镜像预装**：把 agent 需要的运行环境（python+依赖/git/node/凭据注入点）预装进镜像，让「装东西」这件事不必发生（沙箱假故障的主要来源即「装东西被挡」；全权下虽不挡，但预装同样省时且更可重复）。
   （备选：若实测发现容器内沙箱（Linux bwrap/Landlock）零误拦、零额外耗时，可改回 `workspace-write`；切换须在对比试验**开始前**完成，中途不得换档。）
4. **一票一执行器、不中途换**（否则无法归因；要换＝新票）；
5. **对照数据必须留档**（原始报告、时间线引用、盲评记录进 notes，供复核）；
6. 一切改动走工单，共享守卫期望值只在 main 侧改一次。

## 七、风险与未决

- **最大风险＝把「加一个可选后端」做成「重写平台」**：六面耦合若一次性全换，出问题无法归因；故**按面分票、逐面零回归**推进，且面 A 的接口契约先行；
- **模型可用性**：codex 默认 OpenAI 系；我们现有路由是真源机器级 `model-routes.yaml`——codex 能否接自定 provider 需先验（面 C 的第一步）；
- **观测面等值性**：dsh 的实时流是私有格式，codex 另有格式——UI 必须走归一后的稳定接口（否则一家的格式变更就会打破可见性）；
- **两套并存的隔离成本**：会话目录、日志、结果文件都按「票 × 执行器」分治，任何一处串了都会污染对照结论（面 D 专验）；
- **未决（待宿主定）**：①**盲评执行人**（宿主评 / integration 评 / 两评对照）；②**双跑的任务数**（主口径＝同一任务双跑，故样本量＝跑几个任务，建议先 3-5 个）；③**`default_executor` 取值**（建议 `dsh`）。
- **已定（本轮宿主拍板，录此备查）**：一票一个执行器、开票即定不得中途改（红线 4）；**不做角色级执行器**（票级已足够，少一层归因歧义）；容器内**默认全权**、边界改由最小挂载面承担（红线 3）。
