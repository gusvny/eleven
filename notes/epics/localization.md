## 背景与问题

宿主 260907 分发语境发问「变成英文版有多大工作量」。实测中文面：引擎 ~4700 行（大头注释）、插件客户端 ~3100 行（用户可见字符串仅数百）、场景/测试 ~680 行、docs ~2200 行。初估「C 档=一周＋156 场景全量重验」**经质询后修正作废**：场景族绝大多数跑桩 agent（fixture 驱动，不真吃 prompt），prompt 语言几乎不相干——真要验的是几条真 agent 泳道活表现。

关键事实两条（宿主已确认口径）：
1. **中文 prompt 的 agent 会跟着输入语言走**——英文工单/英文项目 → 产出基本英文，功能无损；
2. 真正刺眼的是**引擎骨架词**（「前段交接」「验收报告」「红灯：…」等 prompt 模板围栏与日志文案）——英文内容包中文骨架，属 B 档引擎文案面。

## 宿主红线与约束

- **排序约束**：本 epic 全部实现票排在命名清理（t260907-04/05/后续目录重构票）**之后**——同一批文件不让两张 epic 来回踩；
- **场景断言耦合**：任何改日志/骨架文案的票，grep 中文锚点的断言（「红灯」「隔离台就绪」族）必须同票英文化/双语化，不许留一夜假红；
- **双语优先于硬换**：宿主自己是中文用户，硬英文替换（A 单做）会让宿主界面变英文——除非宿主明说，一律走 i18n 带语言档；
- **prompt 行为验证**：C 档落地后开 2-3 条真 agent 泳道验证阶段行为不走样（活体验证，不是 156 场景重跑）。
