## ⓪ 说人话版（一分钟读完）

**两个目录，两种东西。** notes 是草稿纸：聊天里聊的、我随手落的讨论稿、epic 进度、
问题台账——写完就是为了用完就扔，全丢了系统照样跑。docs 是归档柜：只放「确认过
是真的」的东西——设计准则、接口契约、操作事实，写给人和 agent 看，要说人话。

**东西怎么进柜子？** 不是等大扫除，是三个时机顺手放：①一张工单收尾时问一句
「这票有没有留下值得归档的事实？」；②一个 epic 做完，我把整个故事整理成文归档；
③每天有个小管家巡一遍柜子（见下）。

**柜子里的东西怎么保证没过期？** 有个**总账本**（就是现在的文件列表，每天
更新）：每篇文档「上次核对是什么时候」记在账上——`verified`，核对过=里面
说的和代码现实还对过账。每天一个小任务自动查：这篇文档描述的那片代码，从
上次核对之后有没有人动过？动过就记「待重核」排进队列，每天核对一两篇，
核完更新账。**账本每天必记一笔**（哪怕没东西可核也记「今天巡过了」）——
账本要是几天没动，一眼就知道是管理员没来上班，而不是「都新鲜」。agent 查
文档时新鲜度跟着账本自动来——太久没核的，它会多长个心眼先去对照代码。
文档文件本身不被机器碰，只有人写的内容和「我覆盖哪片代码」的声明。

**工单怎么用这些文件？** 规矩一句话：**要求写死在票里，背景给全文链接**。
「要做什么、验收标准」必须抄进工单正文（票是铁账，不能引用会变的东西）；
调查报告、立项单这类背景材料直接在票里给文件路径（泳道拿到的是冻结快照，
不会中途变样），票里写「必读」是合法的。

**代码改了、文档没跟上怎么办？** 以前只能立个「欠条」（sync 债）挂着。以后：
写集改革落地后，票声明要改哪个文档就直接改（人审兜底），欠条机制自然消失。

**UI 上能看到吗（本次新增）？** 现在界面里的书架只摆 docs。计划：chat 里我说的
「草案写好了：notes/discussions/xxx.md」直接是可点的，点开就在界面里看；
书架也加一个「工作区」页签摆 notes 全家（讨论稿/立项单/台账），文件上盖
「草稿·讨论中」的章，和 docs 的「定稿」一眼区分。UI 草图见
notes/discussions/260904-notes-ui-mock.html。

> 宿主口述定义（260904，原话口径转写）：

## 一、两目录 = 两种记忆（定位节底稿）

| | notes/ | docs/ |
| --- | --- | --- |
| 本质 | 过程记忆（工作台） | 沉淀记忆（知识库） |
| 内容 | 讨论纪要、快速想法、epic 实现追踪、KI 台账 | 沉淀下来的事实、设计准则 |
| 写法 | 快、糙、随手，无规范约束 | 说人话、遵循撰写规范、给人看 |
| 生命周期 | volatile——丢失不伤系统 | durable——**验证事件后**沉淀（拍板/收口/测试在案即触发，不限时点） |
| 消费者 | 宿主（通常经 main 侧 agent 代查检索）；**工单 worker 零依赖** | **agent 的 context**（知识库插件/index.json）+ 人 |

流向：notes 产生讨论 → 讨论产生工单 → 工单构建系统；**验证事件**（宿主拍板/工单收口/
测试在案）触发沉淀，验证过的事实从 notes 沉淀进 docs。notes 是原料与脚手架，docs 是
成品档案。两条细则（260904 宿主质询后定稿）：

- **工单引用铁律**（260904 修订3，宿主质询「蒸馏不好呢？dev-lane 两个 agent
  要从不同角度理解」后定稿）：分界=**契约 vs 背景**——契约性内容（做什么/
  边界/验收/写集/拍板口径）自足进票面（拍板产物转写，无损）；背景性长文档
  （调查报告/epic 主档/讨论档）**全文引用**且**必须已提交**：泳道 worktree 自
  基线切出，worker 读到的即冻结副本——契约不可变性由 git 机制保证，不靠内联
  （KI-014 教训是共享可变文件并发写，非此场景；未提交件进不了泳道=引用落空）。
  全文优于切片：预切片=开票人视角垄断，developer×integration 双 agent 从各自
  角度消费同一份全文，各自知道该看哪节。「必读」标注合法（票面点名=工单上下文
  显式扩张）；worker 禁区=自主浏览 notes 当知识库（点名可读，未点名不翻）。
- **位置=生命周期，不由文风决定**：讨论型 doc 级文件（多人沟通前精写的提案）
  仍留 notes——它是提案不是定稿；拍板后**当场毕业**进 docs（迁移+frontmatter
  定稿+索引重跑），不等 epic 结束。docs 不设 draft 态：agent context 不加载
  未验证草案（07 事故「设计带病」教训不在 docs 层复刻）。

## 二、背景与问题（三个张力，各有实证）

1. **沉淀没有触发器，所以经常不发生**：design-doc-sync-t260903-07 债挂账未消
   （工单推翻定稿条目，docs 写集外只能手立债）；KI 台账账实漂移（260904 一日
   连翻 6 行）；ops 手册靠 project-lifecycle 票「顺便」更新。**收口 ≠ 沉淀自动发生**，
   现状全靠人记得。
2. **「文档先行」口径与实况错位**：知识库设计.md §1 写「先写文档、达成一致再做」，
   实况是先行的角色=notes 讨论档（t260904-07 讨论档即先行件），docs 收的是事后
   验证过的定稿。原则没死，落点要改写。
3. **docs 腐化是双向的**：正向=该沉淀没沉淀；反向=现实变了 docs 没跟（sync 债类）。
   docs 是 agent 的 context、是设计×实现一致性审查的基准——**docs 撒谎，agent
   带着谎干活**（07 事故「设计带病」发生在讨论档已致阻塞级交付，发生在 docs 层
   危害更大）。

## 三、目标（四面，草案）

- **面A 沉淀管线**：**三层触发（260904 定稿方向）**——票级=收口验收清单显式
  一问（「本票沉淀了什么？」，答「无可沉淀」即过，机械记录）；epic 级=收尾
  由 integration 起草成文批次（跨票叙事/决策史）；**每日=freshness 维护
  （见面B）**。沉淀操作=从讨论档/KI 结论/契约增量抽取，按写作指南写进 docs，
  index 重跑。引擎软闸不做（等 t260904-12 三态闸落地再议，不造会被 SKIP 的承诺）。
- **面B 新鲜度与账实（260904 宿主补案重设计）**：不做 status: drifted（人维护
  的状态声明必滞后——KI 账实核对教训）。改做 **`verified` 时间戳＋每日任务**：
  - frontmatter 新增 `verified`（≠`updated`：updated=内容变过[人/票维护，会烂]；
    verified=事实被对照现实核对过[机器/agent 落，不撒谎]）。**内容变更走 §5.2
    人审，verified 元数据由核对动作机器落**——规则写明豁免。
  - 每日定时任务三层（temporal Schedule，dispatcher-scan 先例；大概率独立成票
    doc-refresh-scan）：Tier0 机械=index 重建+frontmatter lint+戳维护；Tier1
    **因果陈旧检测**=每篇 docs 声明 `covers: [<代码路径>]`，比对 verified 之后
    covers 范围内有无 commit（相关代码动了才陈旧，非日历陈旧）→ 陈旧进复核
    队列；Tier2 agent 复核=每日 1-2 篇按队列优先，核对关键主张 vs 代码，过则
    盖戳，报告摘要进 index。
  - agent 消费面：index.json 带 verified+陈旧信号；提示词规则「引用陈久未核
    文档的关键主张前先对照代码复核」——「docs 是 agent 的 context」获得信任
    梯度，不再全信。
  - index.json 重跑机制化（build_index.py 从手跑变任务内跑）；epic 收尾全库
    抽查保留作兜底。
  - **中央列表制（260904 宿主提案，取代 per-doc 戳落文件）**：verified 日期、
    陈旧标记、复核队列、`generated_at` 心跳——全部机器态进**一个列表文件**
    （index.json 扩展），**每日更新、无条件**（generated_at 每天必变一行、
    必有一笔提交——列表自己的 git 史就是心跳，「没更新」与「死了」可分辨，
    KI-046 静默失效免疫）。收益：文档本体**零机器写入**——§5.2 豁免条款整个
    不需要，人审只管内容；戳+心跳+派生态三件合一。判定三行：心跳新+戳新鲜
    =可信；心跳新+陈旧=正常待核；**心跳旧=全体存疑先修巡检**（Schedule
    执行史为第二层铁证）。
  - **分工铁律：人写的在文件里，机器维护的在列表里。** frontmatter 只留
    声明物（`covers` 覆盖路径声明、tags——作者写、§5.2 人审管）；列表管全部
    机器态（每日任务管）。盖戳节奏仍事件驱动：verified 只在真核对发生时更新
    （沉淀时首打、covers 动了经队列复核后重打、没动不碰）；每日收尾一笔提交；
    90 天最长年龄兜底盖 covers 漏声明的暗陈旧；漏打自愈=队列每日从 git+
    frontmatter 全量重算。
  - **agent 消费（不靠自觉靠结构）**：知识插件消费的就是 index——新鲜度字段
    并进条目，agent 查文档自动带着信任梯度（零新习惯）；charter 一行兜底
    规则「引用 docs 关键主张前看新鲜度，陈旧先对照代码」；泳道 worker 读
    冻结副本=看到基线时刻的核对状态，语义恰好正确（对基线工作）。代价两条
    如案：迁移时路径键重映射（罕见一次性）；裸读文件无戳（面 E 查看器从
    index 渲染覆盖主路径）。
- **面C 反向同步闸**：工单推翻 docs 定稿条目时的正路——现状=手立债条目当临时
  真源。候选⚑：docs 写集开放策略（票可改 docs、走人审）/ 收口强制核对「是否
  推翻任何 docs 条目」（落债或随票改）/ 债条目登记机制化（闸感知在位债清单）。
- **面D 规则落字**：知识库设计.md「文档先行」改写为「讨论先行（notes）＋定稿
  沉淀（docs）」；notes/README 毕业规则补全；写作指南（设计文档写作指南.md）
  地位确认；terminology 补词条（沉淀/毕业/临时真源）。
- **面E notes 的 UI 可见性（260904 宿主令追加）**：现状=工单台知识视图（📖）只
  消费 docs/，notes 对宿主是「agent 说有、自己看不见」的黑洞。目标两面：
  ①**chat 落盘链接可点**：会话消息中的仓内文件路径（agent 落盘物）渲染为
  文件卡片（名称·类型·更新时间·一句话摘要），点击在 UI 内打开查看器——

  ②**书架双页签**：知识视图扩「docs 定稿／notes 工作区」两页签，notes 页

## 四、宿主红线（提案，随拍板定稿）

- **docs 是 agent 的 context**：docs 变更走 §5.2 文档 review（人审定稿）；
  agent 不得把 notes 当上下文（既有规则重申）。
- **沉淀不造新事实**：只沉淀已验证的（工单收口在案/测试在案/宿主拍板在案），
  docs 不收猜测与计划。
- **准入=说人话**：撰写规范+frontmatter 不合格退回（写作指南为准）。
- **volatile 的诚实推论**：过程性结论（KI fixed、epic 拍板、债清偿）不得只活在
  notes——收口时要么沉淀进 docs、要么在台账登记，否则等于丢失。
- **工单引用**（260904 修订3 定稿）：契约内容自足进票面；背景长文档全文引用
  （必须已提交，泳道读冻结副本）；worker 禁自主浏览 notes 当知识库，票面点名
  可读。
