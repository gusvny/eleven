## 背景与问题（全部有实案证据）

1. **Docker 假死（当日 3 次）**：`docker info` 挂住无回包、CPU 却不高（票面记录原话「socket 连通但 90s 无回包，负载仅 3.5、无客户端堆积」）。根因面＝测试容器把**宿主目录经 NFS 共享挂进容器**（实测挂载表：`.lane/<票> → /repo`、`→ /repo-nm`、`/profile`、`/fixtures`、凭据文件等），容器 create/rm 全要过宿主 NFS，卡住即守护进程在内核里等。物证：`docker rm -f sandbox-agent-t260919-01 ... timed out after 30 seconds`。**非资源问题**：宿主磁盘 487G 空闲、内存 87% 空闲、OrbStack 数据 6.3G。
2. **残留累积**：Docker 内积 **279 个卷**（`stage-console-*` 98、票号前缀 102、`ui-shot` 2、`zz*` 4、共享台 2），6 个已停容器含**已关票留下的台**与孤儿共享台；**21 个 node 控制台端口**（3000 段）为阶段控制台残留。拆台动作（`compose down -v`／`rm -f`）恰是最易卡的操作 → 卡一次留一批残骸 → 正反馈。
3. **争用致假红/假封**：多泳道并行跑批撞同一套共享台 → 供给装配超时 → **0 跑**；判据未接通 → 被计成 tests-fault 轮次 → t260916-25 撞上限 5 封票（卡 12 小时+）；t260919-02 集测同样 0 跑（仲裁判 pass 才未被封）。
4. **自动化自身无存活保障**：守夜脚本探活**挂在同一个假死 daemon 上**（两次整夜停摆）；console 重启时它随之消失。**注：守夜脚本（`.sandbar/night_autopilot.py`）不在版本库，宿主令 260920「先不动」——本 epic 只治仓内面（`server/plugins/temporal-tools` supervisor）。**
5. **多写者撕裂会话（2026-09-17 事故记录已实证，本 epic 收口其机制面）**：测试台/夹具实例加载 `temporal-tools` 插件后，其 keepalive 会给**生产 Temporal 上所有 running 票**起 worker（无项目/实例过滤）→ 同一票两个 poller → **同一会话档被两进程交替写** → 下一个恢复进程报 `corrupt Zstandard session log: complete frame contains a torn JSONL record`。当日实测：会话档 `zstd -t` 完整、逐行 `json.loads` 全合法（6495 行）——**不是文件坏，是多写者交错**；这也解释了引擎检疫探针（逐行校验 JSON 合法）为何判「健康」而不检疫。260920 复查：泄漏台已不在（3199 已清），但仍有 21 个阶段控制台端口在册、其中多个 cwd=`.lane/t260916-25` 且**连接生产 7233**。与会话撕裂并行的第二条路径＝agent 进程在写一半时被打死（Docker 假死 / worker 自退取消活动）——两条路径同产同一种报错，本 epic 都要收。

## 目标（六块，先判据后机制）

1. **判据块**（零串行代价）：供给失败形态机械归环境红、**不计入 tests-fault 轮次**、票面点名；等待设预算，超预算按 `ENV_FAIL` 三态收尾而不硬等。
2. **补拉隔离块（高危优先）**：worker 补拉（keepalive/ensure）必须**限定本控制台所属实例/项目**，禁止为异实例的票起 worker；会话档多写者检测或单写者保证。
3. **残留与泄漏块**：清现存残骸 + 「关票即拆台」硬约束 + sweep 覆盖 `stage-console-*`／`ui-shot-*` 卷 + 泄漏台自灭；连续 N 轮跑批后卷/容器/网络**零净增**。
4. **自愈块**：仓内 supervisor 对 Docker 探活加**硬超时**，判死即自动重启并唤醒受影响票；留痕可查。
5. **争用块**：**只锁供给窗口**（探活+ensure+拆台）的全局锁，场景执行保持并行；配「等待预算 + 超预算走判据块」（宿主 260920 定调 B5-a + B5-c：串行代价秒级～1 分钟，不是整段排队）。
6. **挂载块（最重、最后）**：收窄宿主目录挂载面（能省的去掉，必需的改「命名卷 + 起台时拷入」），从根上降低假死概率。

## 红线

- **console 3099 不重启不停不占用**（照旧）；仓内 supervisor 改动上线后由宿主择机重启生效。
- **诚实口径不退化**：真产品红**绝不许**被当环境红放掉；判据宁窄勿宽，签名/字段畸形一律保守计轮（引擎既有纪律）。
- 不改 Temporal 执行语义，不新增任何推进入口（无 set-stage / force_stage / 改状态面）。
- 守夜脚本（仓外资产）本轮不动，仅登记其失效事实。

## 验收标准（epic 级，可判定）

1. **供给失败/等待超预算** → 票面点名且**不计轮**（构造腿：伪造供给失败，断言计数不涨 + 留痕含「不计入」）；
2. **补拉隔离**：异实例/异仓控制台在场时，断言生产票**不被其起 worker**（构造腿：起一个指向同 Temporal 的台，断言它的 ensure 不为本仓票补拉）；同一票同一时刻**至多一个 poller**（可断言/可观测）；
3. **双泳道并发跑批**：第二个**在锁门口排队**而非撞 daemon，两张都出完整结果；供给窗口耗时 ≤ 阈值且**不随套件时长增长**（基线：全套件 232 条墙钟 ≈286s）；
4. **Docker 假死**：探活在硬超时内判死 → 自动重启 → 恢复后自动唤醒受影响票（不再整夜停摆）；
5. **残留零净增**：连续 5 轮跑批后卷/容器/网络/控制台端口计数零净增；
6. **负腿**：真产品红不被当环境红放掉；
7. **回归**：单泳道正常跑批墙钟不退化。
