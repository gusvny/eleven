## ⓪ 说人话版（一分钟）

控制台就三栏：**左边是你管的面**（项目、工单、会话），**中间是执行器面板**（看状态、看流水、配东西），
**右边是平台的 chat**（我们不做，也不碰）。

今天要重做的是**左栏与中栏**：入口归并（原来那些散落的入口收进 tab）、票详情做成中栏浮层
（不跳页）、项目有自己的**形状与颜色**（不用千篇一律的圆点）、会话有**句柄**（能一眼认出哪个是执行器）。

**口径写文档、不写界面**（宿主多次实报"过于 informative"）：界面上只留控制与事实。

## 一、目标（收录口径）

1. **左栏**：品牌并入第一行（零额外高度）、项目列表（带徽标与项目色）、展开项目的工单列表、会话区
   （句柄、新建两入口、切换）。
2. **中栏**：面板 tab 归并（Overview / Epics / Ledger / Alerts / Inspection / Metrics / Docs / Grants / Settings）、
   状态看板删除、Metrics 从侧栏迁入、**票详情＝中栏浮层**（含 Spec 块与泳道图）、epic 详情、面包屑。
3. **项目身份**：徽标＝12 色 × 6 个非常见轮廓 × 3 种结构；同一项目在左栏与面板里一致。
4. **会话**：`sessions.json` 落项目、句柄命名（`executor` 为固定名）。
5. **一条铁律**：右栏恒为平台 chat；票详情/看板/驾驶舱一律住中栏；浮层**永远只有一层**（下钻用面包屑回退）。

## 二、范围外（明确不做）

- **不自建 chat**（右栏是平台的面，本仓只做装饰）。
- **不改平台的壳**（顶栏取消、品牌并入左栏是"我们的插件不动平台、只在可用插槽里做"）。
- **不动顺带发现的面板缺陷之外的东西**：那些已由既有票修过（列表契约、告警面、请求卡、文案门）。

## 四、与相邻 epic 的分工

- **`concurrency-limit`**：上限与**顺序的语义**归它；本 epic 只管那些块**长什么样、从哪进**。
  UI-1/UI-2 与 CL-2/CL-3 有面重叠 ⇒ 顺序上 CL 先。
- **`project-executor`**：执行器的运行面（唤醒、短活会话、授权与动作账）归它；本 epic 只做外壳。
- **`inspection`**：Inspection tab 的**内容**归它；本 epic 只保证它作为一个 tab 进得来、排得对。
