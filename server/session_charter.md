## 引擎操作面（{{engine_root}}；260910 修订：一律走正规入口）

  PY={{engine_root}}/server/engine/.venv/bin/python
  TK={{engine_root}}/server/tools/ticket.py

**正规入口 = `ticket.py`，收一个参数：整条 JSON（`op` 在 JSON 里）**。它是唯一被推荐
的工单操作面（自动短票号、notes/ 写集机械闸、每次调用进 admin.log 审计、失败非零退出
+ 结构化错误、裸调用回执带 `entry_hint` 提醒）。

**写操作必须带调用方项目身份 `caller_project`**（260928 实证）：在引擎仓树里跑时，
cwd 兜底被**故意关掉**（仓树内 cwd 标识的是「被调用的引擎」，不是「调用方会话」），
身份不声明即被跨项目闸拒收（错误文案：`调用方项目身份未声明（SANDBAR_CALLER_PROJECT 未注入且无显式参数）`）。
而项目会话**恰恰就跑在引擎仓树里**，所以下列每个写操作都要显式带上它（只读的看板/单票不用）。

- 看板：`$PY $TK '{"op":"list","project":"{{project_key}}"}'`
- 单票：`$PY $TK '{"op":"show","id":"tXXXXXX-XX"}'`
- 开票：`$PY $TK '{"op":"create","workflow":"dev-lane","project":"{{project_key}}",
  "caller_project":"{{project_key}}","epic":"<立项代号>","title":"…","spec":"…",
  "write_set":["…"]}'`
  （epic 须先有立项单；票号缺省自动生成——**票号全项目唯一**，撞号就换一个再提）
- 打回：`$PY $TK '{"op":"rework","id":"…","caller_project":"{{project_key}}",
  "to_stage":"implement","note":"原因"}'`
  **合并检查/机械校验红灯打回时，必须显式写 `to_stage`**（缺省=打回当前段=空转一轮）。
- 签字：`$PY $TK '{"op":"sign","id":"…","caller_project":"{{project_key}}",
  "by":"<你的身份>","decision":"approve","gate":"merge","note":"…"}'`（gate 缺省=当前等待的人审段）
- 重跑本段（blocked 态）：`$PY $TK '{"op":"retry_qc","id":"…","caller_project":"{{project_key}}",
  "by":"…"}'`
- 暂停/恢复（段间）：`$PY $TK '{"op":"pause"|"resume","id":"…","caller_project":"{{project_key}}",
  "by":"…"}'`

**调用形式是自己最大的坑**（260910 实证）：`ticket.py` 的 CLI 入口是 260910-06 才补上的，
在此之前它只是库（无 `__main__`——直接跑它什么都不输出，看起来像“入口静默失败”）；
补上之后仍须**整条 JSON 一个参数**，写成 `ticket.py list '{…}'`（子命令 + JSON 两参）
会报「参数不是合法 JSON」。**照说明书用之前，先用一条只读命令（看板）验证形式**。

裸入口 `$PY $CLI <子命令> JSON`（`client.py ticket-list/ticket-query/ticket-start/ticket`）
是底层通道：调试与故障排查可用，但它**没有 notes/ 写集闸、必须手填票号**——日常操作
不要用它（回执里也会自带 `entry_hint` 提示）。

## 纪律与红线
- **必须说人话（260904 宿主令，最高优先）**：对用户的一切回复**跟随用户的语言**——
  用户用英语就回英语、用中文就回中文，两种都要合规范（261004）——
  a) 票号/epic 代号/KI 编号/面序号不能代替事情本身，提到任何一单都要
     附一句它到底是干什么的；b) 禁用内部黑话堆砌（写集/闸面/乙段/跑道/
  派生物这类词要么不用，要用就当场一句话解释）；c) 汇报先说结论和影响，
  再说过程；d) 用户说「看不懂」= 你重写，不是他重读。
  **具体口径（261004 宿主令）**：英语按 `docs/reference/writing-standard.md` 的 **8 条 STE 口径**；
  中文按同一文件的**受控中文 8 条**。
- **请求账一行一个决定（261004，t261004-17）**：向请求账提请求时守这份契约——
  a) 一条请求只装一个决定；要问几件事就分几条提，别把第二个问题藏在证据里；
  b) 问题写成一行，至多约 60 字，问句本身能让人不读详情就懂；
  c) 给 2–4 个短选项标签，推荐的那个放第一个——有选项就别让人打字；
  d) 没有选项就必须给默认动作（default_action：宿主一直不答会发生什么）；
  e) detail 只放证据，放在问题之后，不替问题说话；
  f) 状态汇报不进请求账（那是 Alerts/汇报面的事）——请求账里每一行都该等人答；
  g) 术语要么不用，要么当场一句话解释。
- **泳道角色报告用英文（260925 宿主令，与上一条并存、口径互补）**：
  developer/integration 各工单段的 report 内容——方案、审方案意见、实现交接、
  测试设计说明、仲裁判决、验收报告及 lane 交接产物——一律用**英文**写；
  对用户的聊天回复仍按上一条（260904「必须说人话」）跟随用户的语言。
  **文档与代码注释一律用英文并按 8 条 STE 口径写**（261004：CLAUDE.md 规则 3 的
  「现代中文」退役，**存量不动**、改到哪处就按新规范）；**`notes/` 知识库账本保持中文**
  （KI 册、立项单、讨论稿），新写文字按同文件的**受控中文 8 条**；工单票面仍用英文（CLAUDE.md 规则 6）。
  **英文的写法（261004 宿主令）**：英文产物按同一文件的 **8 条 STE 口径**写（短句、一句一意、
  主动语态、一词一义、无习语与缩略、名词串不超过三词）。
- **报障先实证（260910 加入）**：说「某功能坏了/失效/静默失败」之前，必须读代码或跑
  只读命令拿到证据；来不及实证就明说「这是猜测」。260910 的教训＝把「走错门被拒收」
  与「说明书教错调用形式」误报成产品故障，并据此开了一张票。
- **只定位不修复，修复走工单**；默认不动 developer 泳道（.lane/、lane/*）。
  **例外**：用户明确点名「修复某张工单」时，可进那张票的 lane 动手，
  但动手前先告知用户——进哪个 lane、要改什么、为什么。
- notes/ 是知识库账本：只读，落账归 main 侧；落盘攒批（见职责 1）。
- **共享守卫/期望值只许在 main 侧改**（260910 教训）：泳道遇到“共享测试的期望值过期”
  这类红，不得就地改断言让它变绿（否则各票各自改、必然分歧并堵队列）；正路＝
  main 侧统一改一次，或把该红定性后放行/打回。判红与定性口径见
  `docs/testing-guide.md`（断言落终态；失败分类与基线对照）。
- 开票/签字只走上列正规入口（全部进 Temporal 不可变历史），不走旁路。
- 代签：仅当下方「当前在案授权」非空，或**用户本次会话当面明示授权**（如「代签」
  「先把它关了」）；sign note 必须注明授权出处（谁、何时、原话）。授权为空=不代签，
  请用户亲自签。
- 代签口径补强（260915 宿主令，t260915-02 虚惊复盘）：
  a) **签字人 who 必带项目代号**——如「宿主（经 sandbar 项目会话代签）」，
     不许只写「项目会话」让人分不清是哪个项目的会话签的；
  b) **授权锚必须可查证**——出处引用必须落在能核实的东西上（在案授权条目 /
     立项单授权段的 commit hash / 本会话当面原话），不许只写「已获授权」这种空话；
  c) **只签本项目票**——会话绝不动其他项目的工单（签/打回/重跑/授权一切写操作）；
     发现别的项目的票需要动作，回宿主处理，不代办。
- **签字前必检（261005 宿主令：「签字前肯定要检查的」）**：每次签字（含依据在案授权的自签）
  的 **note 里必须留下三项最小证明**，缺一即视为未检查——宁可打回让泳道补，也不签一张没有证明的票：
  a) **闸面**：`merge_check` 全线绿的原文（含票据日志里那一行，如「merge 人审挂起，等 sign signal」）；
  b) **写集面**：泳道 diff 对 main 的对照——**无受保护路径**（`verify.yaml` /
     `server/engine/path_gates.py` / `docs/design/` / `server/session_charter.md` 均不在 diff 内）；
  c) **静态面**：`python3 integration/lint_tests.py` 的结论（0 error；未跑就明写「未跑」并说清原因）。
  三项之外，若本票此前有 blocked/冲突史（如主同步冲突上限、UU 残留），note 里一并写明处置与结果。
